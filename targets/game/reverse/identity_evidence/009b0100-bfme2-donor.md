The converted symbol is `_Rva009B0100Vp6BlockFilter`. Its original library function name and owning context remain unproven. The retained address identity, context identifier, member identifiers and callback identifiers come from the existing bank. The donor's `ApplyReconLoopFilter` name is not adopted.

The tested checkout base is `76f3fd7c4af821e01573cdf5ecd663f4a668823f`. New evidence is the Open BFME 2 donor `Code/Libraries/Source/VP6/LoopFilter.cpp`, function `_ApplyReconLoopFilter` at game.dat RVA 0x001C0AF0. The complete copied donor was inspected directly. Its scalar local order, retained row step and inline fragment predicate address the earlier stack-home, switch and pointer-induction blocker. ## ABI and layout

The function receives seven 32-bit stack words and returns with plain `ret`, so it uses caller stack cleanup. The context is entry ESP+4. The remaining words are stored to context offsets +0x0C, +0x10, +0x14, +0x18, +0x1C and +0x20 in argument order. There is no receiver adjustment. The fourth word is stored but never read, and remains an opaque `int arg4` rather than an asserted buffer pointer. The flag pointer at +0x18 is dereferenced as bytes; its index is multiplied by the full-width stride at +0x1C. Only the low mask byte at +0x20 is used by tests, although the argument store is full-width.

Pixel addresses are sums of the +0x10 word and the words at +0x78, +0x7C or +0x80. The source retains the bank and neighbouring landed sources' pointer-at-plane and integer-offset view. This describes the witnessed address arithmetic and does not establish the original VP6 declaration. Fragment starts use +0x84 and +0x88 as 32-bit counts. Dimensions +0x90 and +0x94 undergo logical right shifts for chroma, while local loop comparisons are signed. Line strides are read at +0x98 and +0x9C. Every accessed field and width is witnessed by this target; allocation size and donor names are not used as type evidence.

The setup call at +0x6A pushes context and limit in cdecl order, cleans eight bytes and consumes EAX as a pointer. Its declaration is the existing `int *(__cdecl *)(Rva009AF530Context *, int)` for `g_rva01356e68SetupBounding`, already owned and recorded at VA 0x01356E68. A cast connects the target's opaque context view to that canonical declaration. Filter calls push work, stride, pixel and context, then clean sixteen bytes, sometimes after two consecutive calls. All filter results are ignored. The source uses the bank's opaque writable `void *` work contract and a four-word cdecl filter callback.

## Actual callbacks and globals

The complete dispatch installer at RVA 0x009B0D60 stores the scalar setup RVA 0x009AF490 or SIMD setup RVA 0x009C2930 into VA 0x01356E68. It stores RVA 0x009AF570 or 0x009C2970 into VA 0x01356E9C, and RVA 0x009AF6A0 or 0x009C2BA0 into VA 0x01356EBC. These are body addresses, not thunks. Every callback was decoded in full and checked with `checked_callees.py`. Their extents, returns and empty outgoing-branch inventories are retained in `decoded-extents.json`; raw disassemblies and checked inventories use `retail-<rva>.log` and `checked-<rva>.log` under `build/vp6-loopfilter/`.

The scalar setup reads context+0x34, clears 512 dwords, writes signed correction ramps and returns the +0x400 midpoint on both paths. The SIMD setup reads the same member, adds +0x400, aligns to 32 bytes and writes six initialization dwords at work+0x00 through +0x14. It leaves that address in EAX at its return. The existing `initPattern` source declares a void return; that name and declaration do not prove the callback return consumed here. The decoded EAX data flow does, and no helper declaration or pin is changed.

The scalar edge callbacks read the fourth argument as signed correction dwords and write byte pixels. The complete MMX vertical callback additionally writes scratch qwords at work+0x18, +0x20, +0x28 and +0x30 and reads them back. Thus a const work contract would be wrong for this dispatch family. The MMX horizontal callback reads the three initialized qwords and does not write work. Neither filter dereferences its first argument. These different work layouts are deliberately represented by an opaque writable pointer, not an invented common payload class.

The limit lookup at +0x49 reads dwords indexed by argument two from VA 0x012D7B58. The three callback slots and that table retain BFME 1 address identifiers; no BFME 2 data address remains. The gate must validate all relocation bindings because a masked probe alone cannot do so. The raw incoming-reference screen finds no direct call, direct jump or stored entry-VA hit. That is negative screening evidence only, so no original semantic identity is claimed. ILT checking of the retained address-derived name reports UNTESTABLE because this library body is not a thunk target.

The signed-count aggregate change is rejected; no inline assembly, pin invention or baseline change is used.
