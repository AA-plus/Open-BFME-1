## Hypotheses and measured results

The first new hypothesis was that an explicit last-index temporary, rather than direct subscript evaluation or an iterator receiver, changes the arithmetic folding and the lifetime of the saved element-slot address. Retail's fourth size computation at +0x2A1 decrements the node distance before shifting it and applies the final index decrement in a separate LEA. The bank folds both decrements into a displacement of -0x21. Unchanged output or a larger mismatch refutes a particular spelling. Direct indexing, direct assignment and using `begin()` are worse; splitting the signed decrement leaves the original result unchanged.

An unsigned size local creates the useful expression boundary. Retail's separate node decrement appears again, and the masked difference count decreases. The unsigned local followed by the signed last index is the simplest candidate with that result. Inline size helpers, a reference to the size temporary and an output parameter reproduce the same result. Signed size helpers and explicit iterator-field locals are worse. The result does not establish that the residual is purely register allocation: the retained body still emits ADD followed by DEC where retail emits LEA, and it schedules the iterator-segment shifts differently.

The search-loop hypothesis was independently justified by the decoded unsigned comparisons, which do not decide the induction variable's declared type. Signed induction does not improve either candidate. While and do-while forms remove a repeated size computation and shorten the body; the infinite for loop with a header break reproduces the corresponding ordinary for loop. Materialising the switch value does not improve the body. Moving case 4 or giving it its own tail is worse. Late deque aliases, slot-address pointer locals and copying one slot with `memcpy` do not improve the candidate. Standard copy, swap and memmove forms are worse. These spellings are experiments, not recommendations to change the algorithm.

The constructor-visibility hypothesis used the actual wrapper constructor, not a donor name or allocation size. A native set member followed by volatile trailing fields emits the constructor's 65-byte instruction shape without masked differences. A nonvolatile variant has nine differences. Both visible, inline and explicitly noinline constructor variants leave the target at the same mismatch. Their independent helper decodes are `build/009f0fa0-close-bank/57-visible-set-constructor-helper.log` and `build/009f0fa0-close-bank/58-visible-set-constructor-volatile-helper.log`. No additional constructor definition is retained in the bank, and this helper comparison is not a new identity claim or strict relocation certificate.

The finite non-EH generator offers only an unused wrapper's store-order change and supplies no useful choice at the count divergence. Its raw receipt is `build/009f0fa0-close-bank/family-search.log`, and the search sources and result are under `build/shape_search/c7a2981e452e4f4e935aa2f0af2ed13b/`.
