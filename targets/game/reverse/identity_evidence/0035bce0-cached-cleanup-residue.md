# 0x0035BCE0: cached cleanup index and receiver lifetime

## Result

The saved reconstruction remains the preferred bank. No trial reduced its measured distance, and the strict byte comparison fails. The ledger remains the generated dump at revision 3fdaab72788e574b4301e64661777b9fdc8e2b42. The new helper hypothesis is refuted for the tested source forms; this does not prove that clean C++ recovery is impossible.

The retry hypothesis was that an inline table pop, destruction and release operation would preserve the index and adjusted table receiver without changing the already matching prefix. Retail preserves both values across node destruction and deallocation. The bank instead reloads the index after those calls. The refuting observation is that the inline cleanup operation reproduces those tail lifetimes but moves the receiver into EBX and the entry into EBP, changing the prologue and failing byte equality.

## Instruction mapping

| Retail region | Explained difference |
|---|---|
| +0x00 through +0x7B | The bank's non-relocation bytes agree, including the recursive child loop, sibling loop and unlink. |
| +0x7C | Retail loads the entry index into ESI. The bank loads it into EAX. This accounts for the first differing ModRM byte at +0x7D. |
| +0x7F | Both forms load the table pointer from receiver +0x18. |
| +0x82 through +0x95 | Retail advances its saved receiver by +0x0C before deletion, retains the index in ESI, and loads the head into EDI. The bank delays the receiver adjustment and uses EAX for the index and ESI for the head. These operations explain the operand changes and the shorter pre-deletion sequence. |
| +0x96 and +0x9C | Retail calls the node destructor and operator delete here. The bank calls them at +0x93 and +0x99, so their relocation sites do not align. |
| Candidate +0x9E | The bank reloads entry +4 after node deletion. Retail continues to use the cached index. This is a lifetime difference, rather than a uniform register substitution. |
| +0xA4 through +0xAB | Retail pushes ESI and copies its already adjusted receiver into ECX. The bank pushes EAX and computes receiver +0x0C with LEA. The release call moves from +0xA7 to candidate +0xA8. |
| +0xAC through +0xC8 | The following pointer test, pooled cleanup, deallocation and epilogue are shifted by one byte. Retail RET 8 begins at +0xC6; the bank's RET 8 begins at +0xC7 and ends outside the recorded extent. |

## Boundary, calls and layout

The complete target decodes from RVA 0x0035BCE0 through its RET 8 at +0xC6, followed by INT3 padding. Every conditional and unconditional branch remains inside this extent, and there is no tail jump, indirect call or EH registration. The first incoming stack word is the address of a child-list head; the second is an entry pointer. The only validated direct caller is the recursive CALL at 0x0035BD19, which pushes the child pointer, pushes the address at node +8, sets ECX to the saved receiver and calls ILT 0x000196D7. That complete five-byte thunk jumps to the target. Raw searches found no other E8/E9 candidates to the body or this thunk. This establishes the decoded calling convention, not the original source decoration or all possible indirect callers.

The complete directly reached bodies were decoded and checked with checked_callees: sibling operation 0x0035B3D0 (118 bytes), node destructor 0x00354A00 (72 bytes), record release 0x00359330 (153 bytes), recursive pooled deleting cleanup 0x00350E00 (38 bytes), its group counterpart 0x00350E30 (38 bytes), and operator delete 0x00881EB0 (21 bytes). Each ends with its decoded return and padding; no requested extent leaves an outgoing branch unreviewed. The target's five ILT calls were separately decoded to their final bodies. Raw files are build/rva0035bce0-run/<eight-digit-rva>-decoded.log, build/rva0035bce0-run/<eight-digit-rva>-checked.log and build/rva0035bce0-run/thunks-decoded.log.

The target reads entry +4 and +8 as dwords, sign-extends the table-row word at +0x0E, and uses a twenty-byte row stride with a node head at +0x10. Record release reads its array pointer at table +0x0C and uses that same stride. The receiver's table subobject is therefore at +0x0C, and its array pointer is at receiver +0x18. The release body decrements the word at row +0x0E, sets a byte at +0x0C, links rows through +0/+4, clears the four-byte string at +8 and compacts four-byte name indexes. These are direct field accesses, not allocation-size or donor-name inference. The bank's m_version spelling describes its local view of the signed load; release's existing declaration treats the same bits as an unsigned reference count. No shared declaration was changed.

The node destructor leaves its +0 link intact, writes a vtable at +4 and destroys owned wrappers at +8 and +0x0C. The wrapper deleting helpers read a pointer at +0, recursively call their own ILT route with a four-byte flag of 1, optionally deallocate when the incoming flag's low bit is set, return the original receiver in EAX, and RET 4. The bank's legacy ScriptPoolObject::deleteInstance(void-returning) call uses that receiver, stack width and cleanup, but does not establish the helper's real identity or pointer return type. Trials 056 and 057 used the independently decoded pointer-returning member-call view through the actual ILT route; they did not improve the bytes.

The sibling callee reads the supplied list subobject at +4, proving why this target passes node +8 while the sibling head itself resides at node +0x0C. It uses the entry prefix +0/+4 and a separate table at receiver +0x2C. All represented entry and node fields are partial layout views; no STL key or payload type was inferred. The target is not a constructor, so constructor unwind states and element-construction type evidence do not apply.

The delete helper's indirect memory-manager call pushes the pointer and flag 1 and removes eight bytes itself. The release helper's memmove IAT call pushes three dwords and removes twelve bytes. These indirect calls were reviewed separately from the target's direct calls; an indirect destination's semantic identity is not inferred from its declaration.

## Experiments and rejected hypotheses

The per-trial sources and unedited probe outputs are indexed in build/rva0035bce0-run/trial-index.json. build/verdict.txt contains the running measurements. The finite trials cover inline and free cleanup helpers; helper argument order; explicit destructor/deallocation; inline entry destruction; scoped and early table views; copied arguments; actual table-member layout; neighbouring runtime and exception flags; processor and frame options; exact node-destructor visibility; aggregate temporaries and slot reuse; reference and value helper arguments; unlink and lookup helpers; the list-subobject parameter view; entry accessors and link-base views; decoded callee routes and return width; a receiver vptr view; child/sibling loop forms; complete-body inline helpers; combined actual callee visibility; recursive static-helper ABI; field-address materialization; and cleanup constructors and destructors.

The exact node destructor remains byte-equal in the visibility experiment (build/rva0035bce0-run/024-node-probe.log). The copied sibling operation also remains exact at 118 bytes, both alone and beside the copied 72-byte node destructor. Their raw probes are build/rva0035bce0-run/075-step-probe.log, build/rva0035bce0-run/076-step-probe.log and build/rva0035bce0-run/076-node-probe.log. The original bank still has distance 49 after all valid measured forms. The scoped release-destructor variant adds an EH frame and emits 266 bytes, contradicting retail's frame-free body. Constructor cleanup temporaries avoid that frame but return to the same 204-byte register swap. Static recursive cdecl helpers use three stack arguments and caller cleanup, contradicting the observed ECX receiver and RET 8. Aggregate fastcall carriers were only a representation diagnostic; they have no independent evidence as original value types and are not proposed source recoveries.

The register-family generator was applied only to the new cached helper context and fed to shape_search with STOP checks before each evaluator. Both generated trials produce the same 204-byte result. Choices and raw outputs are build/rva0035bce0-run/generated-register-choices.json, build/rva0035bce0-run/generated-register-001-probe.log and build/rva0035bce0-run/generated-register-002-probe.log; the retained search manifest is build/shape_search/7fe0ea3d54604053add14d0144bd8c62/result.json.

Trials 039 and 040 were invalid generator outputs: a textual replacement made the free unlink helper recursively call itself. Their shortened bodies do not count as evidence. The corrected complete unlink forms are trials 041 and 042 and reproduce the same register swap. The invalid snapshots and raw outputs remain available rather than being overwritten.

## Reopening condition

Reopen with an independently supported declaration or visible helper that keeps entry in EBX and receiver in EBP through the matching prefix while preserving the cleanup index and adjusted table receiver across deletion, or with new canonical source evidence that changes the tested register graph. A source spelling that reproduces either existing residue without changing the decoded operations is not a new experiment. The current blocker is the cached cleanup lifetime and its global entry/receiver register assignment, rather than an unresolved callee, truncated boundary, proven EH requirement or proof that assembly is necessary.
