# Script message logger at RVA 0x002E5090

The recovered body keeps the bank's address-derived name `Rva002E5090ScriptLogMessage`. The logging role is established by the complete decoded Lua print and error-reporting callers and the call to the matched `ScriptEngine::AppendDebugMessage`. The original source-level function name remains unknown. EA's evidence row identifies `GameEngine/Source/GameLogic/ScriptEngine/LuaScriptEngine.cpp` but supplies no function-name pairing. A caller passing an incompatible value, a different final thunk destination, or a helper with incompatible stack cleanup would refute this reconstruction.

The tested base revision is `50999fae8ba4a973a7c064a55adb598bbaa90b69`. The immutable bank was reproduced before editing: 232 emitted bytes, 49 differing nonrelocation bytes, with the first difference at +0x6E. The complete target is 232 bytes. Its disabled path reaches the return at +0xE7; its buffered-message path restores ESI at +0xE6 and reaches that same return; its emitted-message path restores ESI and tail-jumps from +0xE1 to `StringBase<char>::releaseBuffer` at RVA 0x00887940. Every conditional branch stays within the extent. The instruction immediately after the return is padding. Raw target decoding and the independently checked call inventory are retained in build/rva002e5090/002e5090-dis.log and build/rva002e5090/002e5090-callees.log.

The target reads one four-byte incoming pointer from [ESP+4] before saving ESI, scans its bytes to the zero terminator when nonnull, and returns without popping an argument. Complete decoded bodies for `luaB_print`, `Rva002E51C0LuaErrorFrame`, the Lua notification callback, and `io_debug` pass text pointers or string literals to ILT RVA 0x0003EBAD, which jumps to this body. The callers reclaim the outgoing stack storage. This establishes a cdecl C-string input with no hidden return storage; the result is unused. The function's name retains its address because the callers establish behavior rather than the original decoration. Caller bodies and checked inventories are retained under build/rva002e5090/ with address-based log names.

The constructor route is ILT RVA 0x00017BD9 to `AsciiString::AsciiString()` at RVA 0x00062030. The complete nine-byte constructor takes its receiver in ECX, clears the first pointer-sized member and returns that receiver in EAX, without stack arguments. The bank's inline address-derived storage wrapper preserves that call through a member-function pointer and holds one four-byte pointer. The target has no exception registration or unwind states. The static registration callback at RVA 0x00C6FE40 loads the same storage address into ECX and tail-jumps through destructor ILT RVA 0x0000D828; that route reaches RVA 0x0005EE90 and then releaseBuffer at RVA 0x00887940. This is single-string ownership, with no array elements or constructor-failure cleanup. Raw constructor, registration and cleanup-route logs are retained in build/rva002e5090/.

The complete 64-byte concat body at RVA 0x00887D60 reads its incoming pointer and signed length at [ESP+4] and [ESP+8], uses ECX as the string receiver, and returns with `ret 8` on every path. Its existing buffer length is zero-extended from the word at buffer+4. The complete 56-byte reverseFind body at RVA 0x00072C40 reads the receiver's pointer, the word at buffer+4 and character bytes from buffer+8; it never writes the string. Both found and not-found paths share `ret 4`; the high block at +0x32 returns to the main scan at +0x10. Its argument is read as one byte from a four-byte stack slot. The target calls it through ILT RVA 0x0000C342. The complete 224-byte removeLastChar body reads the reference count at buffer+0, unsigned length at +4, capacity at +6 and character storage at +8. It performs copy-on-write, writes those same fields and character storage, and returns without popping arguments. These decoded accesses independently support the canonical `StringBase<char>` declaration and its eight-byte header. The AppendDebugMessage route is ILT RVA 0x00028CE0 to RVA 0x0033C8E0. Its complete body reads the first incoming argument as a reference to a four-byte narrow string, appends it through StringBase<char>, passes character storage to the resolved `AppendMessage` callback and returns with `ret 8`. Its dynamic callback receives one C-string pointer and has caller cleanup. The logger itself has no indirect or virtual call in its decoded retail extent. The global-data pointer and script-engine pointer use existing recorded declarations at VAs 0x012ED5C8 and 0x012F076C; game source contains no numeric image-address literal.

The new hypothesis was that the declaration-only reverseFind call concealed its read-only behavior from MSVC. Native getLength and str accessors alone emitted 230 bytes with 46 reported differences and lost the persistent ESI buffer value. Adding the existing matched reverseFind implementation as an inline, noinline template definition preserved the call and allowed the compiler to retain the pointer across it. The bank with that visible helper reached 232 bytes and three differences, confined to the null-path assignment order; the native-accessor version reached 232 bytes with exact instruction bytes after relocation masking. The visible helper itself also reproduced its full 56-byte extent. It is an inline COMDAT rather than a second strong definition. Raw outputs are build/rva002e5090/visible-bank-probe.log, build/rva002e5090/visible-native-probe.log, build/rva002e5090/final-source-probe.log and build/rva002e5090/visible-helper-probe.log. Every trial source, unedited output and hypothesis is retained in build/rva002e5090/; build/verdict.txt records the running measurements.

Rejected hypotheses were changing the manual length helper to the native getLength forwarding accessor while retaining the bank's manual scan, and reversing only the manual null-path assignments. Neither reduced the original 49-byte difference count. A full accessor replacement without a visible reverseFind definition introduced a second global pointer load after the call. The matched native form removes the bank's unused pointer local and manual length helper. Byte equality alone is not the identity evidence; the decoded callers, routes, widths and ownership above are the independent checks.

The final source removes that macro and calls canonical inline clear, which emits the existing private `?releaseBuffer@?$StringBase@D@@AAEXXZ` call. No new pin is needed.
