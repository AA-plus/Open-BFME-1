# RVA 009AB530 probability tables

The new hypothesis is that the typed multidimensional arrays and in-class byte-read helper in Open BFME 2's `Code/Libraries/Source/VP6/ConfigureEntropyDecoder.cpp` at game.dat RVA 001BBF70 recover the frame and register allocation missing from the saved pointer-loop reconstruction. A full-size compiler probe with any non-relocation difference would refute the direct-port hypothesis. The port preserves the BFME 1 address-derived name and canonical callee declarations; the donor's exported VP6 name is not asserted for BFME 1.

The complete retail decode is retained at `build/vp6-donor-run/009ab530-decode.txt`. The sole return is RVA 009AB75B, followed by INT3 padding. Every conditional branch and direct jump stays inside [009AB530, 009AB75C). There is no exception registration, unwind cleanup, tail jump, virtual call or indirect call in this function. The 556-byte extent includes internal alignment instructions.

The complete 625-byte caller at RVA 009ABFC0 ends at 009AC230 and is retained at `build/vp6-donor-run/009abfc0-decode.txt`. At 009AC101 it loads the byte at context+1AC into zeroed EAX, pushes that word at 009AC107, pushes the context at 009AC108 and calls 009AB530 at 009AC109. It discards eight bytes at 009AC10E. The target reads the pointer argument and tests only the low byte of the second word. This agrees with the existing `unsigned char *, bool` cdecl declaration and void result. No receiver adjustment or hidden return storage is present.

Complete decodes and checked-callee logs for DecodeBool 009B4800 (114 bytes), bfmeGoUSC 009AC550 (40 bytes), BuildTable 009AAFE0 (200 bytes) and BuildTone 009B64A0 (331 bytes) are retained in the same raw-evidence directory. DecodeBool reads the state pointer followed by an integer probability, writes state offsets +4, +8, +C and +10, reads the input pointer at +14, returns an integer bit in EAX and uses plain RET. GoUSC reads its pointer and integer bit count, accumulates the returned bits in EAX and uses plain RET. BuildTable reads context followed by a const byte array, stores into context+5BC and uses plain RET. BuildTone consumes one context pointer, calls the already-recorded ready function pointer with no arguments and uses plain RET. Each target call supplies these arguments in the decoded order and performs cdecl cleanup.

Byte stores and loop strides prove the context regions at +3A0 as [2][11], +3B6 as [2][3][6][11], +560 as [2][14] and +63C as [64]. These agree with the landed neighbour 009AB320's context layout. The primary decoder starts at +150. The branch at 009AB5C6 skips only the default copy; the branch at 009AB5EA guards indices 1 through 63 and BuildTable. All later probability passes execute on either flag value, preserving the 11-byte previous-value array. No container payload or owning allocation is involved.

The six DIR32 references use the already-recorded `g_rva01143064` symbol and byte addends 4C, 64, A4, C0, DC and 268.
