# ProductionUpdate update contract retry

This note records the first run's measurements and final bank at its handoff. The second run's comment restoration, corrected indexed-loop bound, and callee-binding results are recorded in `0029e330-comments-and-bindings.md`.

The target remains a partial reconstruction. Its ledger extent is RVA 0x0029E330, 4685 bytes, and the tested checkout revision is 3c0d7786a9ce170ad6beda247ae1baccdae232b4. The best measured full body is `build/production-update-retry/preserved-getter-name.cpp`. It emits 4663 bytes and has 3537 differing bytes after the probe masks its 205 relocation sites. The first differing byte is +0x27. The strict scoped comparison has 4073 differing bytes, four unresolved call sites, and a 22-byte size deficit. These diagnostics do not establish a recovery or verified indirect-call contracts.

## Hypothesis and refutation

The retry tests whether current landed declarations remove ABI and receiver mistakes in the old bank before register allocation is investigated. Current evidence includes the 111-byte Rva0029C380 getter, the 125-byte Rva000F9780 float method, the 37-byte address-derived AsciiString getter, Object::getControllingPlayer, and Player::getProductionTimeChangePercent. A native call with a different receiver, stack cleanup, hidden return placement, or field footprint would refute an adopted declaration. Unchanged machine code would refute a declaration change as a code-generation improvement, even if the declaration is more accurate.

The old bank does not compile against the current ascii_string.h because its explicit StringBase<char>::str specialization occurs after instantiation. Moving the specialization before that include restores compilation. That compatibility baseline emits 4698 bytes with 3692 masked differences and a first difference at +0x1C. Raw logs are `build/production-update-retry/probe-baseline.log` and `build/production-update-retry/probe-compatible-raw.log`. The older author score cannot substitute for this measurement.

## Checks and reopening criteria

The preferred candidate's strict scoped gate fails in `build/production-update-retry/gate-preserved-getter-name.log`; its complete receipt, resolved bytes, compiled bytes, and selected REL32 routes are retained alongside it. Unresolved sites are the two upgrade getter calls, the indexed getter copy, and the one-argument bitset setter. No pin was invented and no fallback masking was enabled. The compiled body is 22 bytes short. The first mismatch is the receiver register at +0x27, followed by spill-slot differences and the model-condition read moving before its floating branch. Restore these from evidenced declaration or lifetime changes rather than repeating an unchanged register experiment.

The final saved bank has score 0.2356, measured by the repository banking tool. `probe-bank-final.log` repeats 4663 bytes and 3537 masked differences; `gate-bank-final.log` repeats the failing strict comparison with 4073 differences and the same four unresolved sites. `check-csv-final.log`, `pin-consistency.log`, `class-gate-bank.log`, and the source-text check `name-regression-bank.log` pass. The declaration ownership check rejects the unlanded scratch source with zero ledger rows; `declared-unmatched-candidate.log` retains that result. It is not a passing source-landing gate. No game source, ledger claim, symbols pin, shared header, tooling, or policy file is changed. No full gate is required for this evidence-only bank, and no exact target bytes are claimed.

Reopening requires an independently justified change that resolves the spill/lifetime ordering, a verified route for the retained opaque getter declarations, or complete type evidence for a different flags or queue declaration. Exact byte equality would still require checking the compiled cleanup states and every applicable indirect ABI. Repeating the unchanged EH, selector-visibility, or string-visibility shapes does not provide a new experiment.
