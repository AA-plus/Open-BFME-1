The recovered symbol is `?rva000BDD20@@YAXPAVINI@@PAX1PBX@Z`. Its owning field and original method name remain unknown. The reconstruction preserves the saved body's descriptive names and address identity. It was tested against revision `9e3be919b10ae956e3c8a13995e0d62f2be1d016` with the source and ledger changes in the working tree.

## Boundary and physical ABI

The complete retail decode covers 385 bytes, from the exception-registration prologue through the nonreturning `_CxxThrowException` call at 0x000BDE9C. The ordinary path returns at 0x000BDE7C with plain `ret`. Every conditional branch stays inside the extent. The throw path is followed by an `int3` padding run. The verified entry thunk 0x0004B204 jumps to 0x000BDD20. The emitted symbol includes one trailing `int3`; that byte also equals retail at +0x181. The scoped gate accepts the 385-byte function and its body guard reports no tail finding. The extent is not enlarged to count padding as progress.

The first live stack argument, at entry ESP+4, is the `INI` receiver. The third, at entry ESP+12, is the destination vector. The function has no ECX receiver, no hidden result storage and no callee stack cleanup. Its preserved four-parameter, void-returning declaration is compatible with this physical cdecl ABI. The second and fourth parameters are unused; their source-level types cannot be recovered from this body. A decoded caller inventory found no named direct caller, and screening found no absolute pointer reference to either the body or its entry thunk. These negative results establish no original owner or callback name.

`INI::getNextTokenOrNull` is decoded completely at 0x008509C0, 29 bytes. It consumes the separator pointer with `ret 4`, calls the imported `strtok`, and returns its token pointer in EAX. The parser supplies null separators on both calls. The narrow string constructor at 0x00888BC0 and release helper at 0x00887940 were decoded over their complete 72-byte and 134-byte extents. ## Reproducible experiment and refutation

The saved body emits 384 bytes with 184 non-relocation differences over the 385-byte retail extent. The new hypothesis was that a typed destination declared before the loop would let the empty vector tag share the destination argument's home, and that the native release helper's source structure would account for the temporary-destruction scheduling. The typed pointer does remove the extra stack slot and reproduces the incoming-argument tag address. Naming the signed decrement result inside `Release_Ref` then recovers every target byte. A scoped named tag, a temporary tag, a block-local destination, separate default constructors, an explicit derived destructor, a reference-form lookup, const release methods and a separate deletion helper did not recover the body. The finite EH search did not improve the saved body.
