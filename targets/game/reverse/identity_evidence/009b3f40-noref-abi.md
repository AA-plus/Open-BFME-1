# 0x009B3F40 reference and ABI verification

This verification starts at `ecab5577078a97e29fb692f61c15f07ee372b746`. The new hypothesis concerns the earlier unobserved-return blocker: the coordinator permits a void emission declaration when no stored entry address or relative caller exists in the image. An incoming candidate would refute that premise and require complete caller decoding. The donor was already used in the previous exact bank; its name does not independently establish a BFME 1 identity.

The complete image contains no little-endian target VA. Screening every byte of every executable section finds no E8, E9 or long conditional relative instruction targeting this entry. There are no positive candidates to validate against instruction boundaries. This is evidence of absent stored pointers and direct rel32 references, not proof that an address cannot be computed. Under the coordinator's explicit rule, the bank's void cdecl emission declaration is retained without claiming the original native return type or additional unread arguments.

The complete 555-byte body has a single plain return at RVA 0x009B416A. The preceding initializer returns at 0x009B3F3C before three INT3 bytes; five INT3 bytes follow the target. All nineteen branches target internal decoded instruction starts. There are no calls, tail transfers, receiver adjustments, EH cleanup or hidden result-storage access. Entry ESP is S and EBX becomes S-4, so the accesses at EBX+8, +12, +16 and byte +20 identify the context, signed-word input, word output and low selector byte in four cdecl stack slots. Source and destination MOVDQA operations require 16-byte alignment. The frame is restored before the plain return.
