## Compiler experiment

The original bank reproduces 154 bytes with 24 non-relocation differences beginning at +0x39. Retail tests mode 1 at +0x36, branches forward to the flags-4 arm at +0x40, then tests mode 5 at +0x3B and branches to the other-flags arm at +0x55. The bank places the flags-4 arm at +0x3B and delays the mode-5 test until +0x50, where it branches backward. This moves one call relocation. The original bank, every trial source and every unedited probe log are preserved under build/load-menu-005694e0/. The baseline log is bank-probe.log.

The new hypothesis was that exposing the native boolean mode predicate to the inliner would preserve the two forward tests before the special arm. Unchanged block placement would refute it. The direct OR predicate in an inline member reaches exact masked bytes in predicate-00.log. Forceinline and a negated AND predicate independently produce the same result in predicate-01.log and predicate-04.log. The split-return predicate forms produce 159 bytes with 76 non-relocation differences and are rejected (predicate-02.log and predicate-03.log). Moving the exact candidate to its final source path, using the ordinary native member declaration and including the existing WindowLayout header still produces all 154 retail bytes modulo the eight relocation operands (final-source-probe.log). The shared getter, not a compiler flag or forced register, changes the block order.

No assembly, barrier, new volatile memory access, new global or duplicate strong helper definition is used. The target has no constructor unwinding or STL value construction, so those acceptance checks do not apply.
