# DX8Caps vendor-specific driver workarounds

The BFME 1 body at RVA 0x0091BE00 is `DX8Caps::Vendor_Specific_Hacks(const D3DADAPTER_IDENTIFIER8&)`. The decoded Compute_Caps body at 0x0091C230 calls it at 0x0091CAA3 with its receiver in ECX and the adapter-identifier pointer in one stack argument. The canonical declaration in dx8caps.h is private, returns void, and takes the identifier by const reference. The target has one return at +0x420, `ret 4`, followed by INT3 at +0x423. All conditional branches stay within the 1,059-byte extent, with no tail jumps, indirect calls, hidden result storage or exception-handling frame.

The NVIDIA, Matrox, ATI, 3Dfx, PowerVR and S3 tests and driver-workaround string literals independently identify the operation. Its NVIDIA arm clears the byte at +0x13B and the DXT1 byte at +0x1A2, then combines the four bytes at +0x1A3 through +0x1A6 into +0x139. Other arms use the existing BFME_DX8Caps_VendorFields layout, including device identity at +0x288, vendor identity at +0x298, logging at +0x2A4, and the 100-byte render-to-texture array at +0x1A7. These are direct field accesses, not a container inferred from allocation size.

Every direct call goes to StringClass::Format at 0x009DBB90 or StringClass::operator+=(const StringClass&) at 0x0091B7E0. Both complete helpers were decoded. Format receives the StringClass pointer on the stack before the format string and optional varargs, uses the imported _vsnprintf with a 512-byte character buffer, returns a 32-bit integer, and ends with plain ret. The target cleans each Format call's stack arguments. The concatenation helper takes its receiver in ECX, a reference on the stack, returns that receiver in EAX on all three exits, copies the source's character buffer including the terminator, and ends with ret 4. Their existing canonical declarations match these ABIs.

The source structure comes from Open BFME 2 Code/Libraries/Source/WWVegas/WW3D2/dx8caps.cpp, Vendor_Specific_Hacks at game.dat 0x0012B9B0. This is a near twin, not an independent identity proof. Its redundant conditional on the DXT5 local before the bitwise OR changes MSVC 7.1 scheduling without changing the value. Porting that expression and its post-store local definitions onto the existing BFME 1 fields removes the saved reconstruction's six register-encoding differences at +0x70, +0x76, +0x8E, +0x90, +0x92 and +0x94. The canonical BFME 1 source flags remain unchanged because this translation unit already owns matched siblings.

The hypothesis would be refuted by a caller passing a different argument representation, an outgoing branch outside the claimed extent, a helper using incompatible stack cleanup or result storage, or a scoped gate resolving a call, string or global to a different retail address. Raw full decodes, baseline and ported probes, oracle output and scoped gate output are retained under build/donor-port/. The ILT oracle reports UNTESTABLE for this library body, so identity rests on the BFME 1 caller, canonical declaration and literals.
