# RVA 009B60E0 prefix-tree builder

The new hypothesis is that Open BFME 2's `Code/Libraries/Source/VP6/BuildHuffTree.cpp` at game.dat RVA 001C69E0 supplies the native indexed node access and in-class sorted-insert helper required by retail's register allocation. A mismatch in a full 441-byte compiler probe would refute the direct-port hypothesis. The BFME 1 pin's address-derived identity is retained. The old bank's packed-child, output and entry type names and all their field names are preserved.

The complete decode is `build/vp6-donor-run/009b60e0-decode.txt`. Every branch and jump remains within [009B60E0, 009B6299). The sole return at 009B6298 follows all four saved-register restores and `add esp, 30C` at 009B6292. INT3 padding follows it. The ledger's 435-byte size ends at 009B6293, inside that six-byte stack-restoration instruction, and is incomplete. This is boundary evidence for replacing the row with 441 bytes. No direct call, indirect call, tail jump, exception registration or cleanup helper occurs.

The complete 521-byte matched caller 009AB320 is retained in `build/vp6-donor-run/009ab320-decode.txt`. Three aligned direct calls at 009AB36F, 009AB3F8 and 009AB49F push an integer count (12, 9 and 12), the frequency dword array and the output dword array in reverse cdecl order. Each group later cleans 34 hexadecimal bytes covering the accumulated arguments of its four calls. The target reads entry ESP+4 as output, +8 as frequency array and +C as signed count; it returns with plain RET and the caller consumes no result. There is no hidden return argument or receiver adjustment. The existing `unsigned *, unsigned *, int` pin and caller's typed cast agree with this contract.

Initialization proves 64 stack entries of 12 bytes, with successor index at +0, signed weight at +4 and packed edge at +8. Edge bit 0 indicates a leaf and bits 1 through 7 hold its symbol or node index. The unused upper bits remain padding: initialization updates only the low byte and actual consumers mask the same initialized bits. Zero input frequencies are set to one in place. The two complete inlined insertion loops compare signed weights and place a new entry before equal weights. Merging copies both complete edge words into output offsets +0 and +4, writes the low byte of `(firstWeight << 8) / sum` at +8 using signed division, and uses a 12-byte node stride.

The complete landed consumers at 009B62A0 (116 bytes) and 009B6320 (175 bytes) are retained with their checked-callee logs. ExpandTable loads either edge word at node index times three dwords, reads leaf bit 0 and the seven-bit index, and writes a 16-bit prefix lookup result. DecodeTree separately processes both edge words, extracts the same seven-bit indices and recursively writes code dwords and length bytes. These independent BFME 1 consumers confirm the output view. No owning object, allocation, destructor or STL payload is proposed.
