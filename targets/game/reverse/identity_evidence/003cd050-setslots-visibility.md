## Identity limits and refutation

The inherited `update`, `lookup` and `setSlots` spellings remain attached to address-derived owners. All are classified as placeholders by the current oracle. Its hash-order tests contradict their exact decorations, so none is claimed as a recovered retail semantic identity. The actual new-row ILT guard accepts the placeholder and the bank-to-source name-regression comparison finds no downgrade. Raw results: build/003cd050-finish/acceptance_pass.log. The name-regression command-line interface accepts Git revisions rather than file paths; because this run cannot write Git, the same module's `regressions` function compares the preserved bank and final source directly.

This recovery would be refuted by a complete caller showing a different receiver or argument ABI, a decoded thunk reaching another body, a value-copy helper with fields incompatible with the layout above, a strict relocation check choosing different call targets, or a byte gate failing either complete extent. A future name correction requires independent identity evidence and must retain the existing descriptive names until that correction is authorized.
