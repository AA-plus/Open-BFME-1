# Object position helper at 0x001C86B0

The source recovery replaces the 302-byte dump at revision 9778a932c11c43066d2674eafc0ce24b7cdcd517. It keeps the bank's descriptive identifier `Object::bfmeGetPosition421AE`. The native `BitFlags<86>::test(6)` expression and the flagged path's post-call sample coordinates reproduce the complete body. The source at its final path has no differing bytes outside relocation operands. The scoped gate verifies the relocation destinations separately. The original EA method name remains unknown.

## Boundary and caller ABI

The complete target has returns at +0x33, +0xF0 and +0x12B, all with `ret 8`. The last return ends at +0x12E and is followed by INT3 padding. Every conditional branch remains inside the extent, and there is no outgoing tail jump. The target uses ECX as the Object receiver, takes position then normal as two four-byte pointer arguments, writes three four-byte coordinates through position, and returns position in EAX. Normal is optional. No hidden return storage or exception registration appears in this body.

The complete 2437-byte Drawable::updateDrawable body at 0x0041BE60 contains instruction-aligned calls through ILT 0x000421AE at +0x850, +0x8AE and +0x8BB. That thunk decodes to a jump to 0x001C86B0. The first call pushes the normal and position stack addresses in that order, forwards the Object receiver in ECX, and passes the returned EAX pointer to the draw module. The other calls push a null normal followed by position. Their subsequent coordinate reads confirm the three-float output. The matched caller source declares the same descriptive method and signature. Raw complete decodes and checked inventories are build/position-001c86b0/retail-decode.log, build/position-001c86b0/target-callees.log and build/position-001c86b0/caller-callees.log.

## Status and native local declarations

The target tests bit 6 at Object+0x90. Its scalar byte access does not establish the complete status type. The independently decoded 220-byte status mutator at 0x001C7370 reads and updates exactly three words beginning at +0x90. Its clear path masks the third word with 0x003FFFFF. The complete 53-byte clear helper at 0x001C60B0 and 43-byte complement helper at 0x001C4BF0 independently show the same three-word representation and 22 valid bits in the final word. This proves an 86-bit status mask and agrees with ObjectStatusBits.h. The source includes the native Common/BitFlags.h implementation and uses BitFlags<86>, rather than copying a template body.

The target independently reads m_contain at +0x1FC and m_layer at +0x314. The name oracle witnesses those names and m_status at +0x90. This translation unit's Object view retains those observed offsets and the actual virtual getDrawable slot. ObjectStatusBits.h has no such virtual declarations, contain field or layer field. The sweep and bfmeobjectlayout Object headers declare getDrawable as a nonvirtual inline accessor, which contradicts the target's virtual call at +0x3A. The local view therefore records the decoded layout without changing a shared header. Matrix3D::Get_Translation and Vector3 come from their native math headers. Coord3D comes from the existing BaseType header and has three Real fields. There is no container reconstruction, allocation or ownership cleanup in this target. The inspected Zero Hour Object.cpp has the same native vector-to-coordinate idiom in a different method, but no target body was ported from it.

## Experiments and verification

The retry hypothesis was that native copy/accessor structure would explain the remaining store and status-test order; identical ordering and offsets after those changes would refute it. The saved body reproduced 302 bytes with 28 non-relocation differences. All offsets are retained in build/position-001c86b0/residue.log. The differences between +0x59 and +0x74 are the status load and test moving before the coordinate stores, plus local store scheduling. The differences at +0x9B and +0xA0 are the cached translation slots being passed instead of the sample slots after the layer call. Correcting the latter leaves 26 differences. The native coordinate setter, generated adjacent X/Y store swap, wider scalar status field and plain inline word-test helper leave that ordering unchanged. The aggregate layout cast emits 283 bytes and is rejected. Native BitFlags::test produces the exact order. A diagnostic BitFlags<192> trial first located this lever, but its guessed extent was rejected as a type declaration; independently established BitFlags<86> retains exact output.

Every trial body and raw probe is retained under build/position-001c86b0. The generated store trials and their measurements are retained under build/shape_search/3a267742e51c4dea9e71103b6c38f17b. The source comparison API reports no descriptive-name regression in build/position-001c86b0/source-name-regression.log. The CLI accepts revisions rather than source paths, so its index-level check remains for the coordinator. The class gate, defined-function census, name oracle and full pin-consistency check pass in class-gate.log, declared-unmatched.log, name-oracle.log and pin-consistency.log in the task directory. add-match.log records the successful scoped byte, relocation, DIR32 and boundary gates and the retired dump row. A build.cmd attempt cannot find Python through the Windows launcher in this sandbox; its raw output is scoped-gate.log. The explicit Git Bash entry-point gate is retained separately. No shared header, policy, tool or generated assembly file was changed, so the header-triggered full gate is not required.

check_csv initially passed in build/position-001c86b0/check_csv_initial.log. After the verified conversion, it reads the still-tracked bank path from the index and fails because add_match removed that file from the working tree. The verified conversion and bank removal stay intact for the coordinator to stage together and rerun check_csv and the revision/index naming check.

The recovery would be refuted by a target branch outside the asserted boundary, a decoded caller with different receiver or argument mapping, a status helper with a different word count or top-word mask, a virtual delegate with different receiver adjustment or stack cleanup, or a scoped gate resolving any call or global operand to another retail address. The retained full decodes and gate outputs allow each observation to be checked independently. The bank's invented bfme name is retained for compatibility and is not presented as a recovered original name.
