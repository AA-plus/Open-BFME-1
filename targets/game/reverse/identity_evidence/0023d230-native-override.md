# RVA 0x0023D230: native override access and iterator lifetime

The 409-byte body is recovered under the bank's unchanged symbol `?rva0023D230@BfmeHordeContainOwner@@QAEPAVObject@@H@Z`. Its semantic method name remains unknown. The body returns the first contained Object whose final template lacks the requested kind bit, or the first contained Object if every contained Object has that bit. With an empty contained list, it makes the corresponding search through the member index and GameLogic lookup, then falls back to the first indexed ID or null. No shared declaration, pin or helper ownership changes are needed.

The tested base revision is f30718cefd55c5159b59c288432617474938f686. Raw logs and immutable trial sources are retained under build/0023d230-worker/. This note describes the local working-tree conversion, not a committed revision.

## Boundary and ABI

The complete decode in build/0023d230-worker/decode-target.log covers [0x0023D230, 0x0023D3C9). All conditional branches remain inside that extent. The return instructions at offsets +0x80, +0x8D, +0x179, +0x185 and +0x196 each pop the sole four-byte argument. The final return ends at 0x0023D3C9, followed by INT3 padding. There is no tail jump, hidden return storage, exception registration, allocation or destruction in this target. The checked inventory is build/0023d230-worker/target-callees.log.

HordeContain's installing constructor writes the secondary-interface vtable at complete-object +0xE4 (build/0023d230-worker/ctor-decode.log). Table 0x010AED58 slot 62 routes through ILT 0x000333A2 to this target. Tables belonging to the AOD and horse variants carry the same route (build/0023d230-worker/vtable.log). The bank's former comment placing this interface at complete-object +0xC4 was incorrect; +0xC4 is the adjustment between the +0x20 contain interface and the +0xE4 secondary interface.

The complete 331-byte Object attack caller at 0x001C77B0 is decoded in build/0023d230-worker/virtual-callers-full.log and checked in build/0023d230-worker/caller-attack-callees.log. At 0x001C788A it calls contain-interface slot +0x68. The installed table 0x010AF048 routes that slot through ILT 0x00027831 to the complete 17-byte accessor 0x00230730, which returns the receiver +0xC4. Its two return paths and receiver adjustment are recorded in build/0023d230-worker/horde-interface-accessor.log and build/0023d230-worker/horde-accessor-checked.log. The caller then pushes kind 0xA3 and calls slot +0xF8 at 0x001C78B0 with that secondary receiver in ECX. It tests the full EAX result and addresses the returned Object's weapon-set storage at +0x264. This supports a single 32-bit kind argument and a full pointer return; it does not prove a const-qualified public method name.

The raw direct-call screening found no call to the target or its ILT thunk. The attack-site evidence is a decoded, instruction-aligned virtual call inside a complete caller, not a raw opcode hit. The other +0xF8 call sites in that log belong to unrelated interfaces and are not used as target ABI evidence.

## Callees and container payloads

Both target override calls reach ILT 0x000022BB and its decoded 26-byte body at 0x00087A80. That body takes ECX, follows the next pointer at +4, returns the final pointer in EAX and uses a bare RET. Every branch stays in the body. Native Overridable exposes this same recursive read-only implementation; the compiler emits its exact 26-byte body in the new translation unit. build/0023d230-worker/strict-target-and-helper-complete.log strictly verifies that emitted helper without changing its existing ledger owner. The separate checked decode is build/0023d230-worker/override-callees.log.

The target's tree increment calls the existing 105-byte `_STL::_Rb_global<bool>::_M_increment` at 0x0082B870. The complete decode follows both the right-subtree and parent-walk paths and ends in a bare RET. It reads the links at +4, +8 and +0xC. The target supplies the node on the stack and removes four bytes after the call, confirming cdecl. See build/0023d230-worker/decode-target.log and build/0023d230-worker/increment-callees.log.

The target's virtual list getter runs on complete-object +0x20. Installed table 0x010AF048 slot 65 routes through ILT 0x00027AF2 to the complete four-byte accessor 0x0021B850, which returns receiver +0x18. The list therefore sits at complete-object +0x38. The target reads its sentinel, its sentinel's first link, and one Object pointer at node +8. The actual writer is installed table 0x010AF048 slot 35, through ILT 0x00034955 to the complete 82-byte body 0x00226790. Its value construction writes only the incoming pointer to node +8; it then writes the next and previous links at +0 and +4 and updates the neighboring links. It immediately reads the same incoming object's template at Object +4. There is no second payload field or value destructor. All writer paths are decoded and checked in build/0023d230-worker/contained-value-complete.log and build/0023d230-worker/contained-value-checked.log. This establishes `list<Object *>` from construction and subsequent dereference, not from the allocation size. The independently decoded 286-byte getMembers body also copies exactly this pointer payload (build/0023d230-worker/hash-registration-decode.log and build/0023d230-worker/list-copy-checked.log).

The member index is the tree at complete-object +0x114 (secondary receiver +0x30). Its insertion caller at 0x00240F10 reads the supplied Object's ID at +0x74 and passes its address to ILT 0x000499F9 with the tree receiver at +0x30. The complete insert_unique body 0x000EEC50 calls ILT 0x0002ED39, which reaches the complete 179-byte value-construction and insertion body 0x000EE420. Both allocation branches copy exactly one four-byte value from the supplied reference to node +0x10. The other writes establish parent, left and right links; there is no second value word. Its ordered comparisons use signed conditions. The target only copies these ID bits and uses them as an unsigned hash key, so the bank's existing UnsignedInt view preserves the representation without claiming a different public ID type. The hidden iterator-result pointer and RET 0x14 belong to this insertion helper, not to the assigned target. See build/0023d230-worker/hash-subscript-complete.log, build/0023d230-worker/value-helpers.log, build/0023d230-worker/value-copy-decode.log and the corresponding tree-insert-checked, tree-value-checked and member-writer-checked logs.

The GameLogic hash buckets are at +0xB4 and +0xB8. Nodes contain next at +0, key at +4 and Object pointer at +8. The complete writer 0x0038E490 reads Object +0x74, obtains the mapped slot through ILT 0x00005E11 and stores the original Object pointer there. The full 99-byte subscript body 0x0038B980 calls ILT 0x000169A5 to the complete 111-byte insertion body 0x00389A20. That insertion calls ILT 0x0002D074 to the complete 23-byte value-copy helper 0x00385E30. The helper reads and writes exactly two dwords, at value +0 and +4. Thus the node payload is an ID and an Object pointer, not a scalar inferred from allocation size or a donor's template spelling. These extents and paths are retained in hash-registration-decode.log, hash-subscript-complete.log, value-helpers.log and value-copy-decode.log under build/0023d230-worker/, with checked inventories in hash-subscript-checked.log, hash-insert-checked.log and hash-pair-checked.log.

The Object layout comes from the shared object.h and thing.h. The template pointer's raw representation is at +4. The local getTemplate accessor views that field as the native one-pointer OVERRIDE wrapper and still returns `const ThingTemplate *`; no competing public signature is introduced. The next override remains at template +4, and kind words are addressed at final-template +0xC8 with unsigned index and shift operations. The six-word view carries the bank's existing declaration; the observed caller accesses word five. The target does not establish the complete ThingTemplate size or all kind enumerators, and this conversion does not claim them.

## Source experiment and verification

The starting bank reproduces 409 bytes with 98 probe diagnostic differences (build/0023d230-worker/bank-raw.log). Every differing byte offset and its containing retail/bank instructions are listed in build/0023d230-worker/bank-difference-map.log. The first relocated call changes position, so this diagnostic count cannot be interpreted as 98 independent register-allocation errors. Retail preserves the list sentinel and first node across the resolver call, materializes Object's template-field address at +0x4A before loading it, and reloads the selected pointer from the node at +0x83. These observations motivated native read-only resolver visibility, wrapper access through the field itself and removal of the first loop's Object local. An unchanged first-loop reload schedule or an incorrectly emitted helper would refute that hypothesis.

Native OVERRIDE as a member or a constructed temporary retains the list endpoints but emits an extra spill and 424 bytes (native-member-fixed.log and native-temp.log). Visible recursion with the bank's manual accessor emits 439 bytes (visible-recursive.log). Explicit saved iterators with pointer reloads, including the repeated-member accessor combination, emit 379 bytes and remove the target frame (scoped-iterator-reread.log and scoped-iterator-reread-accessor.log). Native override plus pointer reloads reaches 409 bytes with 82 diagnostic differences, and adoption of canonical Object keeps that result (native-reload.log and canonical-native-reload.log). Access through a reference to the existing OVERRIDE field then reproduces the complete body, both when the accessor returns the wrapper reference and when it returns the canonical pointer (canonical-wrapper-reference.log and canonical-wrapper-view.log). The pointer-return form is the final source. Trial logs and the source snapshots bearing their log tag preserve the compiler inputs without editing a previous log.

The final source probe is build/0023d230-worker/final-source-probe.log. build/0023d230-worker/strict-target-and-helper-complete.log verifies both the target and the visible helper with real relocation resolution, zero unresolved names, string and constant checks, and the recorded TheGameLogic DIR32 binding. The source uses the same optimization and exception options as the bank and matched HordeContain neighbors; the extra include paths expose the native override implementation. No assembly, volatile barrier, register rotation or new pin is used. The existing descriptive entry and member names are retained. The file-pair naming check passes in build/0023d230-worker/names-exact-file-pair.log; this revision's name_regression CLI accepts revision arguments rather than file paths, so the exact files were checked through its regressions API. The class check passes in build/0023d230-worker/class-gate.log and pin consistency passes in build/0023d230-worker/pin-consistency.log.

The repository landing tool passes its scoped source-claim, byte, string, constant, DIR32 and body-guard checks in build/0023d230-worker/add-match.log. It replaces the dump row, adds the replacement tombstone and removes the bank. An independent scoped run through the approved Git Bash build.sh entry point also passes in build/0023d230-worker/scoped-bash-gate.log. The build.cmd entry point cannot run because its py launcher finds no installed Python in the sandbox; its raw output is build/0023d230-worker/scoped-gate-complete.log. The final declared-definition and class checks pass in build/0023d230-worker/declared-unmatched-final.log and build/0023d230-worker/class-gate-final.log. Final pin consistency passes in build/0023d230-worker/pin-consistency-final.log. The initial CSV check passed in build/0023d230-worker/check-csv-initial.log. The final working-tree CSV check raises FileNotFoundError for the removed bank because its deletion cannot be staged in this read-only Git sandbox (build/0023d230-worker/check-csv-final.log). The coordinator must stage the bank deletion, new source and ledger changes together and rerun that check. The exact conversion is retained. No shared header changed, so this source-only conversion does not require a full gate.

The conversion would be refuted by a target branch leaving the retained extent, a constructor installing a different relevant vtable, a list writer constructing additional payload fields, a caller passing another ABI through the verified interface route, or a strict byte/reference check failing. None of those conditions was found in the retained evidence. The semantic method identity remains address-derived.
