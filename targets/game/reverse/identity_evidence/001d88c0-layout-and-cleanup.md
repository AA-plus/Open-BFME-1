# 0x001D88C0 layout and cleanup retry

## Result and reopening condition

This is a measured partial, not a recovered function. The ledger still owns the complete 2,556-byte dump at 0x001D88C0. The preferred reconstruction corrects position-option and KindOf layouts and uses the canonical Object, AsciiString and Coord3D headers. It also preserves a virtual AudioEventRTS destructor in a 0x70-byte view and the existing opaque capacity-check declaration. There are no new pins or game-source claims.

Reopen this target when a compiler experiment can retain the default allocator temporary's two unwind states without a normal-path destructor call, or when independently verified helper visibility reproduces separate early-return and final-return vector cleanup. A register-only retry is not justified by these results. The remaining terrain declaration discrepancy also needs caller and callee evidence before a strict landing.

The tested base is 575c226488c88f72ccfbe8ccc54983580a4b4e8b. The model is gpt-6.1-sol. Every trial source and unedited probe output remains under build/retry_001d88c0/. Shape-search manifests and additional snapshots remain under build/shape_search/. The append-only running measurement receipt is build/verdict.txt. None of these paths is a tracked attachment or a hosted artifact.

## New hypothesis and refutation

The previous verdict named codegen-order and proposed exhausted inline budgets. This retry tests whether current STLport 4.6 definitions and independently decoded member types remove misleading outlined helpers. The current landed pointer-vector allocation constructor at 0x001D95B0 supplies a readable allocation/proxy layout. The complete position helpers and native math declarations supply an eight-word FindPositionOptions layout. A wrong layout or donor name can produce a plausible masked score, so helper and caller decodes precede the comparisons.

The hypothesis would be refuted if corrected layouts and helper visibility produced no improvement over the measured saved body. The score improves, but the exception-state and cleanup mismatch survives. This supports preserving a corrected partial; it does not establish an exact source shape. The raw differing-byte count actually increases in the preferred candidate because the score also rewards its smaller size error.

## Exception handling and rejected experiments

build/retry_001d88c0/eh_retail.log records all nine retail unwind states. State 0 owns the guarded hidden return; states 1/2 protect the static guard and AsciiString temporary. State 3 owns the allocator temporary at EBP-0x17D; state 4 owns the local vector with parent 3; state 5 owns that same vector with parent 0. States 6/8 own the two audio locals, and state 7 owns the temporary pointer list with parent 6. The complete guarded-return action, including its conditional RET and tail jump, is in decode_remaining_evidence.log. Empty allocator cleanup at 0x000C9DA0 is a decoded RET, not an inferred absent destructor.

The preferred compiled body has seven states and merges vector deallocation into shared exits. Its unwind map and complete generated instructions are in build/retry_001d88c0/native2_best_compiled.log. The corrected visible-base variant matches the opening save sequence through +0x33 but adds an EH reset and omits allocator state 3 at retail +0x87. It then diverges at the clear's state update and the separate early-return base-destructor calls. Its raw output is build/retry_001d88c0/bitset_kindof_probe.log. This is not solely an instruction-register mismatch.

The required eh_levers generator was run before manual shape iterations. throw specifications on the base constructor/destructor make the result worse; copy/erase specifications, EHsc-, STLport no-exception mode and nothrow delete[] do not resolve the discrepancy. Saved generator choices and raw probes are eh_choices.json and eh_000.log through eh_013.log. Those results are allocator_000.log through allocator_003.log, allocator_throw_probe.log and native2_008.log. shape_search refused an empty-assembly hypothesis before compilation; it was not retried through another path.
