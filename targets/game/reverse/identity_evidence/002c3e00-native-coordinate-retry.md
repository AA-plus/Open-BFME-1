## Hypothesis and measured improvement

The new hypothesis was that the remaining residue came from using native Vector3 values where the coordinate copies used Coord3D operations. The actual caller and helper establish three float coordinate fields, and the native headers expose different constructors and inline copy operations for those representations. A same-size output with unchanged or worse resolved differences would refute a proposed improvement. The current declarations address the old callee blocker; they alone do not resolve the old stack-slot blocker.

The original bank reprobes at 382 bytes with fourteen differences after strict relocation resolution. Including the shared Object declaration retains that improvement. ## Rejected hypotheses and reopening condition

Native Vector3 in-place scaling and a by-value position-copy inline retain the original fourteen-difference output. Native Coord3D copy-and-scale emits a longer body with a larger frame. A coordinate position initialized by aggregate copy and passed through the pointer setter changes register allocation and instruction extent. Native Vector3 addition also changes the extent. A visible copy of the actual landed helper, kept inline and noinline rather than adding a strong definition, retains the eleven-difference caller. The helper visibility hypothesis does not improve the target and that copy is absent from the bank.

The complete local constructor and copy alternatives are retained separately. Scalar Coord3D products and the Vector3 array constructor retain the eleven-difference result. Reversing the final product's source operands also retains it. Assigning the position as a complete Coord3D increases the extent; its pointer setter returns to the worse eleven-difference result. Its three-value setter retains the seven-difference result. The direction's three-value setter separates direction Z but adds another coordinate object and enlarges the frame. Shortening that object's native copy lifetime does not remove the extra frame storage. Removing the loop position object while keeping the direction setter restores the frame size but swaps the last/candidate slots and changes the instruction extent. These trials refute those forms as complete fixes.

The supplied family generator produces only the limit/step declaration swap and achieved/last store-order swap already rejected by the preceding recorded run. Its raw choices are build/rva002c3e00-retry-20261011/family-choices.log. Those unchanged hypotheses were not submitted to another search. Further register and x87 respellings are not justified by this result. Reopen with source or type context that preserves direction Z in the required separate slot while copying position Y/Z directly through the candidate record, without enlarging the frame or changing the established instruction sequence.
