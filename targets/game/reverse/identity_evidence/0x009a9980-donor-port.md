# Rational byte sampler at 0x009A9980

The retained name is the bank's opaque `Rva009A9980`. Open BFME 2's `_Scale1D_c` is a donor identity, not a BFME 1 symbol claim. The complete matched 697-byte `Rva009A9AD0Scale2D` stores the actual target address into its horizontal and vertical callback locals. Every decoded indirect call supplies eight dwords in this order: source byte pointer, source pitch, source scale, source length, destination byte pointer, destination pitch, destination scale and destination length. The caller removes 32 argument bytes and does not read a return value. The source uses the caller's canonical signed pitch declarations and unsigned scales and counts.

The complete 155-byte leaf begins after the previous return at 0x009A997B and four INT3 bytes. It ends with plain return at 0x009A9A1A, followed by five INT3 bytes before 0x009A9A20. All branches remain within the extent. There are no calls, tail jumps, EH states, owning members or container types. The raw target decode independently follows every stack argument across the saved registers. Argument 5 is the destination base, argument 6 is the output step, argument 7 is the unsigned denominator and argument 8 is the output count. Its dead stack slot subsequently holds the right byte sample, which explains the earlier false ABI conflict.

The body stores one byte per output step. It divides the sum of the unsigned left and right weighted byte samples and half-denominator rounding term using unsigned DIV. It advances the bracketing pair while the phase exceeds the denominator, subtracts that denominator and updates the complementary left weight. Source length is unused, as in the complete caller contract. These are scalar bytes, not an inferred aggregate payload.

The new hypothesis is that the donor's native scalar left/right samples and indexed for-loop recover the argument-slot reuse and loop scheduling that the bank's explicit byte alias could not reproduce. A residual prologue divergence or changed phase loop would refute it. The old bank emits 161 bytes with 52 differences, first at +1. No assembly or volatile spill is used.
