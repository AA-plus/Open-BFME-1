# W3DDisplay draw bank: typed callback evidence

This note describes the earlier typed-callback baseline for ?draw@W3DDisplay@@UAEXXZ at 0x006F3FC0. The preferred continuation candidate is documented in targets/game/reverse/identity_evidence/006f3fc0-value-adapters.md. At revision 4b710c9dfd3c173e63a4346db2c76b724e0791a8 it emits 1,179 bytes for the verified 1,184-byte retail extent. The raw probe reports 55 differing emitted bytes and 5 missing tail bytes. This improves the original bank by matching the post-delete IAT and callee-saved reload order. This baseline remains evidence rather than a recovery.

The new hypothesis was that the unsigned callback member and externally declared floating constants concealed native declaration information that affected later scheduling. The hypothesis would be refuted if independently justified callback and constant declarations left every instruction unchanged. Both plain float literals changed the reload schedule, and the typed callback completed that reload block. The callback declaration uses the canonical FILE pointer for the third argument; the retail caller supplies zero, so the pointed-to type comes from the reference declaration rather than the instruction stream.

## Identity and complete boundaries

The primary vtable at VA 0x0111EDD0 contains VA 0x004093EF at slot +0x1C. Decoding that ILT entry gives a jump to RVA 0x006F3FC0. The existing W3DDisplay destructor at 0x006EFC20 writes this table into its ECX receiver at +0x1F, and the BFME Display slot order identifies draw. The complete destructor decode and checked inventory are retained as build/draw-006f3fc0/display-dtor-decode.log and display-dtor-callees.log. The target decoration passes ilt_oracle.check with the body RVA passed directly through its Python API. The target has complete returns at 0x006F4103 and 0x006F445F. Every direct conditional and unconditional branch lands on a decoded instruction inside the claimed extent. The second return closes the 1,184-byte function; following padding is excluded.

The main target has no exception frame. The complete capture, save, render, debug-statistics, callback and callback-counter extents were decoded and checked with checked_callees.py. Raw outputs are build/draw-006f3fc0/target-decode.log, target-callees.log, capture-decode.log, capture-callees.log, save-decode.log, save-callees.log, render-decode.log, render-callees.log, stats-decode.log, stats-callees.log, callback2-decode.log, callback2-callees.log, callback3-decode.log, callback3-callees.log, callback-decode.log and callback-callees.log. build/draw-006f3fc0/abi-audit.log records the returns and branch-boundary census. These checks do not assert that the helper bodies themselves were reconstructed.

## Declaration and ABI evidence

The complete 83-byte body at 0x006E8DF0 reads the callback at receiver +0x2C. Its indirect call pushes zero, the +0x30 user-data pointer, and the +0x28 display-interface pointer, then removes twelve stack bytes. The three direct fast paths tail-jump through ILTs 0x000024A0, 0x00047537 and 0x0002F8D8. Their existing mapped methods provide the no-stack-argument member routes; the indirect path independently proves the three-argument cdecl callback shape. Main draw compares the same three callback ILT addresses. The bank now expresses those addresses through the existing address-only j_ names rather than image-address literals. Raw evidence is build/draw-006f3fc0/current-debug-decode.log and current-debug-callees.log; the matched donor was inspected in W3DDisplayDrawCurrentDebugDisplay.cpp.

Capture receives the image pointer in stack slot one and a 32-bit row stride in slot two, and returns with ret 8. Its complete pixel loop reads the three color bytes of each four-byte source pixel and writes three destination bytes, advancing rows by the supplied stride. Save receives image, width and height in that order, swaps image rows byte by byte, and returns with ret 12. Its receiver is unused. The incoming argument representation and cleanup are established; the capture stride signedness cannot be established from additive use alone. The render helper receives ECX and one 32-bit time argument and returns AL equal to one, one or zero at its three complete exits, all with ret 4. The other three opaque helpers use ECX, no incoming stack arguments and plain ret. No new pins were added.

The primary vtable slot +0x74 routes through ILT 0x00042A05 to the complete four-byte getFirstView body at 0x0040F5D0. Slot +0x124 routes through ILT 0x0001B79D to the complete 195-byte screenshot wrapper at 0x006EF5A0. Raw evidence is build/draw-006f3fc0/firstview-decode.log, firstview-callees.log, screenshot-decode.log and screenshot-callees.log. Panorama count at global-data +0xECC is read as a signed dword for fild, signed divide, remainder and loop comparisons. Capture flags at +0xED0 and +0xED1 are bytes; angle and angle step at +0xED8 and +0xED4 are floats. There is no STL value type or constructor unwind cleanup in the assigned target.

The ILT oracle contradicts the inherited captureScreen and saveScreenShot decorations across public, protected and private access variants, including the tested int and long parameter spellings. Their decoded call contracts are usable, but their exact descriptive identities remain unresolved. This run preserves the established bank names and does not rename landed helper rows. Raw checks are build/draw-006f3fc0/abi-audit.log and parameter-oracle.log. The verdict does not claim those names are proven.

Subsequent private-counter trials still emitted 1,186 bytes with 157 positional differences. Additional temporary and statement forms were closed after unchanged results; they should not be repeated without new evidence.

The scoped strict function gate is red in build/draw-006f3fc0/scoped-bank-gate.log. It reports the remaining byte mismatch and the four unpinned opaque helpers at 0x006EB500, 0x006EE800, 0x006F0300 and 0x006F2CC0. The apparent last-call target in that gate output is computed at the candidate’s shifted relocation position; decoded retail actually calls ILT 0x0003809B at +0x493. It is not evidence for changing that existing pin. No game source, ledger row, pin, header or policy was changed. A full gate is not required for this evidence-only bank update.

The source-file comparison through name_regression.regressions reports no descriptive-name regressions in build/draw-006f3fc0/name-regression-files.log. This revision of the CLI expects Git revisions and refuses the generated brief’s OLD-file NEW-file invocation; that refusal is retained in name-regression.log. Pin consistency passes in pin-consistency.log. The final check_csv result is retained in check_csv-final.log.

Reopening is justified by an independently established declaration or visibility property that changes the capture call or counter scheduling. The selected bank proves that declaration information can affect this body’s reload order; it does not prove that the remaining residue needs assembly. Both exact byte equality and strict bindings remain unverified.
