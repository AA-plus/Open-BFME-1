## Boundary and incoming ABI

The complete retail extent is `[0x0047FCF0, 0x0047FFD2)`. All normal paths reach the single `ret 0x10` at `0x0047FFCF`, followed by INT3 padding. No conditional branch or tail jump leaves this extent. The receiver is ECX, the result is a pointer in EAX, and the four stack words are the creation descriptor, entry-data record, font pointer, and boolean. The final boolean arrives in a four-byte argument slot. There is no hidden result pointer for the factory.

The complete caller at `0x00486B10` selects the ENTRYFIELD arm at `0x004871F1`. It sets style bit `0x40`, pushes zero, the font from instance data `+0x184`, the caller's data pointer, and the descriptor, then calls manager slot `+0x5C` at `0x00487228`. The base manager's slot 23 resolves through ILT `0x0003598B` to this body. The derived manager's slot 23 reaches `0x0078F910`, whose two terminal jumps reach the same ILT while preserving those stack arguments. The old one-argument `dispatchFactory` pin therefore does not establish the incoming ABI. No pin or declaration in that other source is changed here.

The base manager constructor at `0x00483760` installs the independently named vtable `0x010F8B60`. Its slot 23, the ENTRYFIELD caller, and the Zero Hour `GameWindowManager::gogoGadgetTextEntry` body establish the factory operation. The old ten-argument decoration is contradicted by the ILT oracle and by `ret 0x10`. The bank's address-qualified owner is retained rather than publishing that decoration. These conclusions would be refuted by a complete caller that sets up a different number or order of arguments, or a vtable route that does not reach the target.

## Cleanup and compiler experiment

The saved bank emits 727 bytes against retail's 738. Probe reports 26 differing non-relocation bytes, with the first at `+0x21A`, where the early return branch targets the shifted tail. Its missing instruction is the eleven-byte `mov dword ptr [esp+0x24C], -1` at `+0x2B5`; the remaining tail differences follow from that omission. Missing bytes count as wrong, giving the coordinator's 37-byte diagnostic residue.

Removing the bank's nonthrowing release declaration restores the final state reset but gives a `0x238` frame and 737 bytes with 546 reported differences. The compiler listing identifies the extra four-byte slot as the saved factory receiver. Replacing the direct style-field expression with the native inline `WinInstanceData::getStyle()` call, while keeping native throwing cleanup, restores the `0x234` frame and all 738 masked bytes. Both const and nonconst getter controls matched; the final source uses the donor's nonconst declaration. The complete canonical string headers, evidenced virtual instance destructor, native DisplayString exception declarations, correct factory vtable slot, integer `winDestroy` return, and removal of all linker alternatenames preserve that result.

Retail FuncInfo `0x00E16A28` contains exactly two states, both transitioning to `-1`. State 0 cleans up the instance-data local using receiver `[ebp-0x1B4]` through ILT `0x00021431` to `0x00499BD0`. That complete destructor releases its four ASCII members at `+0x194`, `+0x190`, `+0x18C`, and `+0x188` and handles the two display-string pointers. The complete instance-data constructor and destructor each have four unwind states with predecessors `-1`, `0`, `1`, and `2`; their actions adjust the saved instance receiver by `+0x188`, `+0x18C`, `+0x190`, and `+0x194` and reach the ASCII destructor. State 1 of the factory cleans up the text local using receiver `[ebp-0x23C]` through ILT `0x0003B304` to `0x0005EEA0`, whose complete five-byte body jumps to the wide release helper. The compiled factory unwind map has the same two predecessors, and both complete cleanup actions compare exactly after resolving their independently verified destructor targets. The normal-path final state reset now matches retail too.

The failed controls retained their trial sources and original outputs: exception-mode generator search, native base destruction, cleanup scopes and scope-exit goto, complete noinline release/copy visibility, unified string type, instance-data vptr and member lifetimes, deferred inline destructor definitions, scalar versus aggregate lifetime, and the two declaration-order controls.
