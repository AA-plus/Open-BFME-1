# Creation helper finish-lane residue

This investigation leaves the generated target and preferred bank unchanged. No source recovery is claimed. The tested revision is ceb21c1bd4d961735f0a9c903c0d3316d6e3623a, and the model is gpt-6.1-sol. Every trial source and unedited probe output is retained under build/001d9630-finish/. The table below is generated from those probe logs rather than copied from author scores.

## Hypothesis and result

The retry tested whether the remaining caller differences came from incomplete helper visibility, array construction, native accumulation accessors, or declarations that name the wrong owner or calling convention. The observation that would refute each caller experiment was unchanged or worse measured caller bytes. No trial improved the assigned body. Independently successful cleanup probes therefore do not justify replacing the preferred bank. The inferred main-method identity remains inherited from that bank and the Zero Hour twin; this run does not supply a matched named caller proving its spelling.

The earlier EH and broad shape searches were read before experimentation. Their failed platform-flag and commuted-addition trials were not rerun unchanged. The new accumulation trials use the native pointer and member accessor forms. The iterator trials change the actual animation subscript expressions. The new allocator-flag trial uses a native command vector, which the preferred bank does not instantiate as a member. Its allocator mismatch is visible in the decoded cleanup, so it is a different experiment from changing flags on the old bank.

## Rejected hypotheses and cleanup limitation

The native accumulation pointer helper and member helper emit the bank's unchanged bytes. Animation iterator indexing and reversed pointer addition also emit unchanged bytes. The SIB generator's output is build/001d9630-finish/sib-choices.log; its choices affect already matching position additions, not the remaining animation subscripts, so those irrelevant combinations were not compiled.

The matched calcRandomForce donor independently reproduces its complete retail extent. The copied bank helper omits retail's array-constructor call. Both selected Vector4 and Matrix3D definitions were preprocessed and inspected in bank-definitions.txt and donor-definitions.txt. Switching to the reference math headers, removing the explicit noinline attribute, changing definition order, removing the STL exception macro, selecting explicit-only inlining, and limiting helper inlining depth do not restore that call or improve the caller. A non-inlined empty Vector4 constructor is still removed. A declaration-only Vector4 constructor produces an inline construction loop and a worse helper. The complete array-construction runtime helper and callback are 0005c600-decoded.txt and 000fbb40-decoded.txt. The callback returns its receiver and touches no fields; it does not independently name the row type.

Providing the real adjustVector body reproduces that helper but worsens the caller. The first helper probe mistakenly requested a longer extent; visible-adjust-callee-probe.log is retained as invalid boundary evidence and is superseded by visible-adjust-callee-complete-probe.log at the decoded return. The precision-consistency flag worsens the main body. No assembly necessity is claimed from these negative experiments.

The canonical forwarding-view trial removes ten unresolved declaration spellings, using existing callee identities instead of adding pins, but changes caller scheduling and worsens its bytes. Its main gate still names normalization and the two visibility operations as unresolved. The separate getter, force, and destructor declaration repairs preserve the closest main bytes. All established bank names are retained in these trials.

build/001d9630-finish/bank-unwind.log and 0x001d9630-unwind.json show agreement of predecessor states and string, command, and handle receiver adjustments. That is insufficient to certify cleanup: the preferred bank emits short tail-call command and handle destructors instead of retail's complete cleanup bodies. The visible native detach body makes both the detach helper and handle cleanup byte exact under the strict scoped verifier, but changes the main caller's conditional cleanup into a destructor call and worsens the target. Forcing the handle destructor inline expands the detach into the main body and also worsens it. The native command vector with restored inlining depth initially uses an imported allocator deallocation call. The static STLport setting restores retail's threshold test and both deallocation paths and passes the command-cleanup scoped byte gate, while making the assigned caller worse.

## Acceptance and reopening

The assigned target fails its strict scoped byte gate. It still has thirteen unresolved declaration spellings in the unchanged bank, and its copied force and cleanup bodies cannot be substituted into an exact claim. Passing helper gates below are isolated evidence, not new recoveries or permission to collect another target. There are no source, pin, shared-header, generated-dump, or production-ledger changes. The original preferred bank remains the closest measured body.

Reopening needs a source-context hypothesis that jointly preserves the main caller's conditional detach call and the complete cleanup bodies, or independent evidence that explains the two retained x87 values and animation address carriers. Repeating commuted additions, the same accessor forms, or the tested matrix-visibility changes is unsupported. The remaining virtual-dispatch checks and a complete native command element-construction witness must also be retained before claiming exact identity and ABI.

The raw main gate is build/001d9630-finish/bank-byte-gate.log. The isolated cleanup gates are handle-cleanup-byte-gate.log and command-cleanup-byte-gate.log in the same directory. check-csv-final.log, pin-consistency-final.log and class-bank.log pass. No full gate is required because no production source or shared header is changed. No Git writes or synchronization were performed.
