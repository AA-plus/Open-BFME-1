# Bezier projectile reset at 0x001F1620

The new bank is partial. It emits 449 bytes against the independently decoded 449-byte extent and has 40 differing non-relocation bytes. Every remaining difference lies between `+0xBE` and `+0xE7`. The strict candidate gate resolves every relocation but fails byte equality. No production source or function-ledger row is changed.

The tested revision is `4fe1d0ff4462cabc7593685dc00559689d55da02`. The model is `gpt-6.1-sol`. Raw measurements are in build/bezier-001f1620/bank-probe.log, build/bezier-001f1620/24-final-bank.log, build/bezier-001f1620/final-measurement.log and build/bezier-001f1620/final-scoped-gate.log. The trial sources and their unedited probe outputs share their numbered filenames in build/bezier-001f1620/. The chronological experiment receipt is build/verdict.txt.

## New hypothesis and result

The retry tested whether the earlier stack-layout diagnosis concealed missing native helper visibility or an incorrect mask construction boundary. The historical bank had an unconditional retail status clear inside a conditional source branch. Correcting that control flow was necessary before interpreting the byte difference. This control-flow claim would be refuted by a retail branch that bypasses the status call; the complete decode instead shows the branch targeting the status-mask construction.

A word-returning flag accessor reproduces the retail register mask without the shift emitted by a boolean accessor. Keeping the mask immutable and initializing its nonzero word inside its constructor reproduces the later mask-store schedule. The prepared bank also uses the actual copy ILT through a typed, inline adapter, the canonical `Coord3D` header, the canonical idle-command enum ABI and a plain float literal. It retains the bank's descriptive words. The model-update adapter appends its address because its changed 304-bit decoration remains oracle-contradicted; the original semantic method name is not asserted as a new retail definition.

The remaining hypothesis is that a distinct source or compiler expansion places the two list-link stores among the early mask stores. A source that makes the strict gate exact would refute the present scheduling blocker. The experiments do not prove that assembly is necessary, or that every possible C++ form has been exhausted.

## Boundary and control flow

The target decodes completely from its aligned entry through its two `ret 4` exits. Every direct conditional and unconditional branch lands on a decoded instruction inside the extent. There is no outgoing conditional branch or tail jump. Padding occurs before the entry and after the extent. The raw complete decode is build/bezier-001f1620/decoded.log; the branch and return audit is build/bezier-001f1620/abi-audit.log; the independent callee inventory is build/bezier-001f1620/target-callees.log. The padding bytes are retained in build/bezier-001f1620/identity-boundary-extra.log.

The kill guard reads the module-data byte at `+0x19`. Its false branch lands at target `+0x165`, where the status mask is built. The condition update and kill belong inside the guard; the status clear belongs outside it. Both AI paths end in full receiver restoration and `ret 4`. The source's unsigned comparison of the module-data word at `+0x38` follows retail's `test` and `jbe`.

## Storage, value copies and ownership

The actual copy helper at `0x000B6BB0` is decoded completely, including its nonpositive-count return and its loop return. It computes a signed count using twelve-byte element strides. Every iteration reads and writes the fields at element offsets zero, four and eight. It does not copy an inferred scalar merely because an allocation happens to be twelve bytes. The complete Bezier path-update caller independently reads those same fields as float coordinates. The bank retains its existing raw three-word path view while including the canonical coordinate declaration for position storage. The typed copy adapter passes all five CDECL arguments, including the empty iterator-tag reference and the null distance pointer, and returns the four-byte result pointer to the path-end member.

The list-clear path reads the forward link at node offset zero, frees each node using the decoded twelve-byte count and resets the sentinel's forward and backward links at offsets zero and four. It invokes no element destructor and never reads the remaining payload. The bank interprets only this header; it does not assert an integer payload from allocation size or the neighbouring donor's `list<int>` spelling. Native list trials used a four-byte trivial value only as a compiler-shape experiment and are not payload identity evidence.

Both model-condition arguments consist of ten initialized four-byte words. The first argument has word four set to the witnessed mask; the second remains zero. The called update reads the two references in this order and operates on the object's forty-byte condition storage at `+0x110`. Following its actual clear-and-set helper at `0x001C5FA0` reaches the complete complement helper at `0x001C4B30`. That helper copies and complements all ten words, explicitly zeros the final word's upper sixteen bits and returns forty bytes through caller-provided storage with `ret 4`. This proves 304 valid bits, rather than the old bank's 320-bit declaration. The local view is corrected to `BitFlags<304>` and the call uses a typed address-claimed ILT adapter. The canonical Object header and the inherited pin's 320-bit signature conflict with this decoded valid-bit count; no shared header or pin is edited. The complete clear-and-set, comparison and command-constructor helpers are retained in build/bezier-001f1620/extra-helpers.log. The complement body and its checked inventory are in build/bezier-001f1620/complement-helper.log and build/bezier-001f1620/complement-callees.log. The status helper reads all three words of its mask and sanitizes the final word to twenty-two valid bits, independently supporting the eighty-six-bit declaration. The target has no exception-registration frame, owning local constructor or unwind cleanup. Exception handling in the AI callees is not evidence of an unwind frame in this target.

## Remaining instruction schedule

Retail loads the sentinel into EAX before the disputed block, initializes part of each mask, stores the forward link at `+0xD2`, reloads the sentinel at `+0xD4`, initializes more mask words and stores the backward link at `+0xE3`. It then copies the zero in ECX to EAX at `+0xE6`. The bank emits both link stores and the intervening reload before beginning the mask stores, then copies ECX to EAX earlier. The frame size, stack addresses, instruction multiset and subsequent code agree. This is an instruction-order difference, not an unexplained wrong member offset or an unresolved call target.

The exact differing byte offsets are `+0x0BE`, `+0x0BF`, `+0x0C0`, `+0x0C1`, `+0x0C2`, `+0x0C3`, `+0x0C4`, `+0x0C5`, `+0x0C6`, `+0x0C7`, `+0x0C8`, `+0x0C9`, `+0x0CA`, `+0x0CB`, `+0x0CC`, `+0x0CD`, `+0x0CE`, `+0x0D0`, `+0x0D1`, `+0x0D3`, `+0x0D4`, `+0x0D5`, `+0x0D6`, `+0x0D7`, `+0x0D8`, `+0x0D9`, `+0x0DA`, `+0x0DB`, `+0x0DC`, `+0x0DD`, `+0x0DE`, `+0x0DF`, `+0x0E0`, `+0x0E1`, `+0x0E2`, `+0x0E3`, `+0x0E4`, `+0x0E5`, `+0x0E6`, `+0x0E7`. The opcode comparison outside that interval is equal after masking relocation operands, and the strict gate resolves those operands independently.

## Rejected experiments

- Processor and optimization flags changed other regions or preserved the residue. The later `/G7` experiment used the improved constructor form and still diverged before this block.
- Inline reset helpers, the complete clear loop, native list storage, allocator-proxy getters and reference or pointer parameters preserve the best schedule. The bounded definition-order search is recorded in build/bezier-001f1620/reset-search.log and build/shape_search/816590c528b24bc6ad4ca2a80e026f0a/result.json.
- A static visible copy helper changes the private calling convention and removes unused arguments. The actual inline, noinline template COMDAT keeps the external CDECL ABI but does not improve this block. The native vector clear wrapper also preserves the best residue.
- Visible model-condition update code does not improve the schedule. Its diagnostic placeholder callees are not proposed as new bindings.
- Value-return mask factories add storage or preserve the residue. Beginning mask lifetimes before an earlier loop or call emits stores in the wrong region.
- Split zeroing intrinsics, copied zero aggregates and constructor array value initialization change the instruction stream or fail to reproduce the complete initialized-mask sequence.
- Single-element mask arrays, explicit copy constructors, empty destructors, const zero masks, native bitset base storage and complete immutable mask construction do not eliminate the list-link schedule.
- Capturing the sentinel across mask construction, moving a reset to that boundary and combining reset and mask lifetimes either worsen the result or preserve the best residue. Initial captured-pointer trials that failed due to a local redeclaration were corrected before judging the hypothesis.
- Alias annotations are unsupported by this compiler. Supported global alias flags change earlier code and do not fix this block.

The family generator's only applicable store choices are in already matching position and scalar-reset regions. They are retained in build/bezier-001f1620/family-choices.json and were excluded instead of repeating the earlier experiments on those regions. New explicit reset-definition choices were tested with the repository's bounded `shape_search` implementation and an evaluator that checks `build/STOP_WORKER` before each compile and preserves a full raw probe.

Pin consistency passes without any pin edit. The canonical-class check passes for the prepared and saved bank. The name-regression API reports no descriptive-to-placeholder substitutions against the old bank. The declared-unmatched source check reports that the scratch candidate owns no ledger row, which is expected for an unlanded partial. No full gate is required by a bank and evidence-only change, and no full gate is claimed.

Reopen this bank with an independently supported source or compiler lever that specifically changes the sentinel lifetime and the early mask-store interleaving, or with a donor that reproduces this block. Repeating the unchanged register choice, local declaration order or flattened zero stores is not justified by the recorded results.
