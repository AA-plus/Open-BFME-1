# Lighting blend at RVA 0x00082C20

The reconstruction in `game/GameEngine/Source/Common/GlobalDataLightingBlend00082C20.cpp` emits all 997 retail bytes exactly, with its single global relocation independently verified. The working-tree ledger replaces the dump row under the bank's existing address-derived method identity. The conversion remains uncommitted. This investigation uses revision `72b4fc2f68f02fc8057bc70d344ba1509a4831f0` and the verified `bfme1.retail-1.03-unpacked` baseline. The model is `gpt-6.1-sol`.

## Boundary and ABI

The complete decoded extent is `[0x00082C20, 0x00083005)`. Its four signed index guards branch to the internal failure block at `0x00082FFF`. The loop backedge at `0x00082EEA` reaches `0x00082C77`. Success returns at `0x00082FFC`; failure returns at `0x00083002`. Both instructions are `ret 12`. Sixteen bytes immediately following the extent are `int3` padding. No conditional branch leaves the extent, and there are no direct calls, indirect calls, or tail jumps. The body does not contain constructor allocation or exception cleanup.

ECX supplies the receiver address. Before the second saved register is pushed, `[esp+8]` holds the first signed 32-bit index, `[esp+12]` holds the second signed 32-bit index, and `[esp+16]` supplies the 32-bit floating factor. Each index must be at least 1 and less than 6. Successful code writes AL with 1; failed code clears AL without defining the full EAX return value. These observations support the retained thiscall declaration with three stack arguments and a boolean-width return. No instruction-aligned caller was found: screening the executable code for direct calls to the body or its verified ILT thunk at `0x00007B53` found no hits, and screening stored body/thunk VAs found no hits. Absence of these hits does not prove that there is no indirect caller.

## New findings and measured changes

The original bank reproduces at 970 bytes. Its 406 different emitted bytes and 27 absent bytes give 433 wrong bytes over the retail extent. The earlier register-allocation explanation was incomplete: the float-pointer reconstruction also keeps its output induction pointer alive into the tail copies, changes address commoning, and contains two wrong third-array destination indices.

At target offset `+0x286`, retail stores at the output pointer plus `0x528`; at `+0x2A0`, it stores at that pointer plus `0x52C`. The old bank instead used destination indices `0x149` and `0x14A`, which select displacements `0x524` and `0x528`. Correcting those writes alone reduces its emitted differences from 406 to 404. The typed reconstruction writes the third record's actual `lightPos.x` and `lightPos.y` fields.

Typed array/member expressions recover retail's argument materialization. An inline copy of the complete sibling helper initially keeps an extra initial output address alive. Storing slot 5 in the active-index member and passing that member into the helper removes the retained address and reproduces the complete pointer setup and tail. This reaches 997 bytes with eight differences. Every emitted byte outside the ambient-green expression and the verified relocation matches retail.

## Resolved mismatch and rejected experiments

The eight-difference predecessor has wrong byte offsets `+0x068`, `+0x069`, `+0x06A`, `+0x06B`, `+0x06C`, `+0x06D`, `+0x06E`, and `+0x070`. Retail loads the factor and multiplies the second ambient-green field before duplicating the retained complement and multiplying the first field. That predecessor evaluates those products in the other order. Both instruction sequences then add the products and write the same field. Its unchanged reproduction is build/82c20-name-restore/before-name-restore-probe.log.

Rejected families include direct tail member reads; advancing typed record and receiver views; identical input/output value types; ordinary versus forced inline visibility and helper-definition order; native release flags; literal versus named subtraction constants; copy-helper parameter materialization and canonical `TimeOfDay` parameter type; product precision and explicit conversion boundaries; sum order and local declaration/scope changes; do, countdown, unsigned, and equality loop forms; a scoped final blend value; and the tested CPU, inlining, intrinsic, alias, size, and float-consistency flags.
