# Filtered polygon writer at RVA 0x00191110

The recovered body retains the bank's name, `Rva00191110WritePolygonTriggersFiltered`. Its owner and the filter's semantic identity are unproven. The literal `PolygonTriggers`, version 5, linked records and coordinate serialization establish the operation without establishing the Zero Hour static method's identity. The BFME2 name supplied in the assignment is not an identity anchor. The tested base revision is `1cf4e545840d726e7a9227b4509ae6a8b169a3ac`.

## Retry hypothesis and result

The current ledger replaces the old pointer-returning `bfmeGoDOA` declaration with the independently decoded by-value getter `Rva00190560::rva00190560(int)`. The retry hypothesis was that its native AsciiString return lifetime would restore the missing EH frame. That hypothesis alone was refuted: the native return still emitted 472 bytes, with 332 masked byte differences and 23 missing bytes. The old bank emitted 472 bytes, with 333 masked differences and the same missing tail. Both immutable saved reconstructions contain the same old body; their score-header spelling differs. Changing the two field declarations to bool without restoring the in-class accessors also left the native-return shape unchanged.

Retail loads all three point fields before its first output call. The bank instead used a reference, permitting field reloads after calls. Restoring the value copy emitted 481 bytes with 234 masked differences and 14 missing bytes. Restoring the in-class boolean accessors emitted 495 bytes with 47 differences. The native ID accessor then emitted 497 bytes with 87 differences in the overlapping extent. Adding the in-class four-byte field accessor produced the complete exact body. The final source was probed again at its intended path and was exact. No x87 respelling, fabricated helper, inline assembly or new pin was used.

Raw trial outputs are build/191110-retry/probe-original.log, probe-native-return.log, probe-bool-flags.log, probe-point-value.log, probe-flag-accessors.log, probe-id-accessor.log, probe-field44-accessor.log and probe-final-source.log in that directory. Each trial source and compiler object is preserved there. The EH generator's /EHsc toggle produced the same native-return shape; its complete search manifest and raw probes are preserved in build/191110-retry/eh-valid-result.json and probe-eh-valid-0.log and probe-eh-valid-1.log. The family generator offered only the previously exhausted count-array lever, so that unrelated change was not repeated.

## Complete boundary and call contracts

The complete decode is build/191110-retry/decoded.log. The target begins with a supported EH registration prologue and ends with its restored registration, `add esp, 0x20` and `ret` at +0x1EE. Padding follows immediately. Every conditional branch remains inside the 495-byte extent, and all loops have explicit exit paths. There is no target tail jump. The independent extent inventory is build/191110-retry/checked-target.log.

After the prologue, the three incoming stack words are head at +0x34, output at +0x38 and filter at +0x3C. No incoming ECX receiver is used. The target returns with no argument pop, establishing its three-argument cdecl view. Both virtual calls load ECX from the filter argument, push the current node, call vtable offset +4 and consume AL. The next iteration's unchanged stack offsets require the indirect callee to consume its four-byte argument. No receiver adjustment or hidden return slot is used at those calls. The source declares only that witnessed slot contract; it does not identify or instantiate a filter implementation. Slot zero is retained as a declaration from the bank and is never called by this body.

The raw direct-call screening hits were validated on instruction boundaries in complete ledger bodies. The only hit for the body or its ILT thunk is the five-byte thunk at 0x000278DB itself. No direct caller was found. This does not prove absence of indirect callers and supplies no semantic class identity. The raw screening and complete thunk decode are build/191110-retry/abi-evidence.log.

All seven output/getter ILT routes were decoded to their actual bodies. Output's canonical declarations agree with their complete bodies: openDataChunk consumes two stack slots and serializes a two-byte version; writeInt and writeReal consume four-byte values; writeByte consumes one byte from a four-byte argument slot; writeAsciiString consumes a reference to one four-byte string object; closeDataChunk takes no stack argument. The full decoded bodies and checked inventories are retained under build/191110-retry/. The source accesses no DataChunkOutput fields and includes the existing shared AsciiString header. No registered shared header exists for the opaque views or DataChunkOutput in this revision.

## Payload and native lifetime evidence

The actual getter at 0x00190560 is completely decoded over 37 bytes. It reads the index and hidden destination stack slots, computes `this + 0x48 + index * 4`, copy-constructs into the destination through 0x00887B60, returns that destination in EAX and executes `ret 8`. Its complete copy helper at 0x00887B60 is 121 bytes: it reads one source pointer, writes one destination pointer and increments the pointed-to four-byte reference count when non-null, with the witnessed lock initialization and enter/leave paths. It does not copy an integer pair or another payload. The target's loop selects six consecutive string objects. No eight-element bound is inferred from the getter or from the donor's declaration. The independently checked inventories are checked-getter.log and checked-copy.log in build/191110-retry/.

The target reads the link at +4, string objects at +8 and +0x34, ID at +0x0C, point pointer at +0x10 and count at +0x14. The byte accessors use +0x32 and +0x40, and the raw serialized word at +0x44 retains its opaque name. The +0x32 boolean store is independently witnessed by the complete 17-byte setter at 0x0018F210. No semantic name is assigned to +0x40 or +0x44. The six by-value string copies occupy +0x48 through +0x5C. The byte at +0x60 is passed directly to writeByte. Each coordinate element contains all three four-byte integers, at offsets 0, 4 and 8, with a 12-byte stride and the decoded signed index clamps. These are translation-unit views of consumed storage, not claims about unrelated members or the complete owner size.

The three color fields at +0x64, +0x68 and +0x6C are loaded as single-precision values and multiplied by the independently read double 255.0. The compiler's native integer casts reproduce the exact calls to the vendored 117-byte __ftol2 body. Its complete decode has no stack arguments, consumes the value in ST(0), returns the integer in EDX:EAX and restores its stack with `leave; ret`; this target uses the low EAX word. It is a compiler helper, not an ordinary C declaration with guessed arguments. Its decode and checked-ftol2.log are retained in build/191110-retry/. The +0x70 float is intentionally serialized twice because both retail calls read +0x70; the third float is +0x7C.

Retail's FuncInfo at RVA 0x00DF53B4 has one unwind state, whose predecessor is -1. Its cleanup at 0x00C06D40 adjusts ECX to EBP-0x1C and jumps through 0x0000D828 to AsciiString's destructor at 0x0005EE90, which jumps to the complete releaseBuffer body at 0x00887940. That helper decrements the reference count, frees a zero-count buffer and clears the pointer. The compiled object's one state has the same predecessor and stack adjustment, with an AsciiString destructor relocation. Raw retail and compiled comparisons are build/191110-retry/eh-retail.log and eh-compiled.log. The state is installed after the getter succeeds and reset before the normal destructor call, matching the temporary's ownership on every path. This target has no constructed owning container and no constructor cleanup to infer.

## Verification and limits

The ordinary relocation-resolving scoped gate passed both through add_match.py and through a separate tools/build.py invocation. It checked the complete body, output/getter/CRT call relocations, the string literal, all three constant references and the body guard. Raw output is build/191110-retry/add-match.log and scoped-gate-python.log. build.cmd's Python launcher failed before invoking the gate in this sandbox; that output is scoped-gate.log in the same directory. No shared header or shim was changed, so this conversion does not require a full gate.

Class-gate, declared-unmatched, pin-consistency and the direct per-file name-regression API passed. Their raw outputs are build/191110-retry/class-gate.log, declared-unmatched.log, pin-consistency-final.log and name-api.log. The supplied name_regression.py command accepts Git revision arguments rather than source paths in this revision; its source-path CLI failure is retained in build/191110-retry/name-file-cli.log. The coordinator must run the normal staged revision comparison after staging the conversion. The old bank's descriptive names and target symbol are preserved.

check_csv.py passed before implementation. Its final working-tree check is blocked by the unstaged deletion of the old bank: it enumerates the bank from Git's index and then cannot read that deleted working-tree path. The raw exception is build/191110-retry/check-csv.log. The sandbox forbids staging. The exact conversion and bank deletion remain intact for the coordinator to stage together and check; the bank was not restored to hide this condition.

This recovery would be refuted by an outgoing branch beyond the retained extent, a getter payload other than the fully decoded string pointer, a different actual destructor route, a mismatching relocation, or a caller proving a different target argument contract. No such contradiction was found in the retained evidence. The owner and filter remain explicitly unidentified, and no guessed semantic pin is introduced.
