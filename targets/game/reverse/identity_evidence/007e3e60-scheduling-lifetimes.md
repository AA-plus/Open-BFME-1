# Upload at 0x007E3E60: scheduling and lifetime experiments

The preferred bank remains unchanged at targets/game/reverse/attempts/0x007e3e60.cpp. It emits 1804 bytes with 61 non-relocation differences against the independently decoded 1804-byte retail body. The scoped strict byte verifier also rejects the equivalent candidate with the canonical decoder declaration. This is evidence for a compiler-shape blocker, not a recovered C++ source or a proof that assembly is necessary.

## Boundary, owner and ABI

The complete target occupies [0x007E3E60, 0x007E456C). Its returns are at +0x93, +0xC6 and +0x70B. INT3 padding precedes and follows it, and every conditional branch and jump stays inside that extent. The vtable at VA 0x01128DA8 has slot 3 pointing to ILT RVA 0x000144A7, which jumps to this body. The constructor and destructor retain the address-derived Rva007E3C20Vp6Stream owner. The bank's YuvUpload007E3E60 and upload names remain address-bearing descriptive stand-ins; the original method spelling is unproven. Direct oracle checking contradicts its decoration, but tools/ilt_oracle.py classifies it as a placeholder, which tools/ilt_guard.py excludes from real-name identity claims.

The upload receiver enters in ECX, without stack arguments or a receiver adjustment. All three returns are plain RET. The lock at 0x00903090 takes no arguments and its result is unused. The unlock at 0x00905B10 returns a byte in AL, which this caller discards. The three decoder call sites push the output address followed by the context pointer. Two calls defer cleanup until an ADD ESP of 16 bytes; the opaque call defers an eight-byte cleanup. Complete decoder paths return without popping caller arguments and consume no hidden return buffer.

The complete 1147-byte 0x009A51A0 decoder writes six dword dimension/stride fields at descriptor offsets +0x00 through +0x14 and four byte-plane/origin pointers at +0x18 through +0x24. Both of its return paths, all branches, its scaled-output path and every descriptor store were inspected. Its already-landed canonical declaration is void Rva009A51A0DecodeFrame(void *, unsigned *). The upload overrides dimensions from signed dword members at +0x30 and +0x34, using arithmetic shifts. The byte flag at +0x38 is tested for zero. No STL container or owning value constructor is involved.

The W3DVideoBuffer vtable at VA 0x0112165C routes the invoked lock slot +0x10 to 0x00739F70 and unlock slot +0x14 to 0x00739C90. The complete lock wrapper passes the address of the pitch word at +0x1C to the subobject at +0x44, leaves the inner call's EAX intact and returns. Its complete 0x00739E70 callee consumes one stack argument with RET 4 and returns the pixel pointer or zero. Both complete SurfaceClass lock implementations confirm the output pitch pointer and pointer return. The existing wrapper source's void return declaration does not express the EAX value that this upload consumes. The bank's address-derived buffer view uses the independently witnessed pointer return and needs no shared-header edit.

The target's single C++ unwind state transitions to -1 and dispatches cleanup at RVA 0x00C54520. That cleanup adjusts ECX to the empty guard at EBP minus 0x10A4, then jumps through 0x0000BFAF and 0x0007BCE0 to 0x00905B10. The bank emits the same guard adjustment, state transition and destructor dispatch. No frame descriptor, pixel array or heap-owned element needs destruction in that state.

| Retail region | Wrong bytes | Decoded cause |
|---|---:|---|
| +0x124 through +0x12D | 10 | Alpha height store and deferred decoder cleanup |
| +0x143 through +0x156 | 17 | Alpha UV anchor and dimension store |
| +0x45E through +0x464 | 7 | Opaque height store and deferred decoder cleanup |
| +0x469 through +0x47E | 19 | Opaque UV anchor and dimension store |
| +0x65C through +0x66B | 8 | Opaque exit reload order |

The stores on opposite sides of ADD ESP target the same physical stack words. The alpha UV region preserves half-height in EDX, constructs the last-row index with LEA into ECX, multiplies it by UV stride and stores the original half-height afterwards. The bank stores half-height first, decrements EDX and multiplies into an ECX stride value. The opaque region has the equivalent ECX/EAX pattern. After the opaque inner loop, retail reloads destination step, UV step and luma step before the receiver. The bank reloads the receiver first. Every remaining byte is in one of these decoded sequences.

## New experiments and refutations

The hypothesis was that authentic helper visibility, primitive widths or object lifetimes explain these sequences rather than an unexplained register choice. Its refutation condition was unchanged residue after a supported representation change, or movement that breaks the already-matching instructions or stack layout. Earlier store permutations, generic flags, lock/unlock visibility, imageSize references and j-source sweeps were not repeated as new hypotheses.

Canonical decoder typing, in-class conversion definitions, row-copy and scalar-width operations, const plane inputs, the canonical byte flag, descriptor-reference access, row storage representations, element-sized copy counts, row-step expression forms, pixel inlines, extracted inner-row loops, branch-scoped descriptors and corresponding unsigned-word dimension stores all retain the original residue. Independent row/column induction variables, descriptor value copies, a by-value UV pointer pair, explicit late UV stores, named dimension producers and unsigned countdowns change more bytes and do not improve the bank. The primitive value dimension accessors worsen the body, including when localized to one dimension or given a mutable receiver; their reference counterparts leave it unchanged. The trial hypothesis incorrectly associated the leaf at 0x007E4750 with height. Complete decoding instead shows a +0x3C read, so that leaf supplies no dimension identity evidence. The target's own accesses and the constructor declarations support the dimension words.

The compiler listings supply a specific explanation for the existing tradeoff. The bank retains named j stack objects and packs the other locals into retail's slots. Independent pointer expressions produce the correct LEA/store sequences but eliminate those named j objects in favor of compiler trip-count temporaries, rotating pitch, pointer, counter and receiver slots. One-word counter arrays and records do not restore them. The finite generated frame-array search tries its two supported object promotions and their combination; each is worse than the unchanged control. The search reports no byte recovery.

The complete landed decoder was copied as an inline definition, with and without noinline, preserving its public two-argument cdecl ABI and avoiding a second strong definition. Its own 1147-byte body matches under the upload's compiler flags, yet the upload still has the original residue. A static-copy control changes the caller to MSVC's private ECX/EAX argument convention, including with noinline, so its changed caller is rejected on ABI grounds rather than interpreted as progress.

A complete typed adapter to the canonical decoder alters the argument lifetimes and fixes the opaque height-store/pop order, but introduces additional producer and pixel-loop differences. Equivalent output-object and context-object adapters have the same result. Localizing the adapter to either alpha call worsens the bank slightly, while localizing it to the opaque call retains the larger penalty. Capturing the context member by reference restores the original residue and loses that store-order change. Capturing the output descriptor by reference retains the larger penalty. These trials supply a specific partial dependency lever, but no closer complete body.

Reopening requires a distinct supported producer or lifetime hypothesis that preserves both the named counter slots and the late dimension-store dependency, or changes the opaque exit reload order without disturbing the pixel loop. These experiments do not establish that no such C++ source exists.
