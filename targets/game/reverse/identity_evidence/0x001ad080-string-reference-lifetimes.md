# Preserved reconstruction for 0x001AD080

The tested revision is `a70037880c51ade71fd7b86b8939786b2aa0b818`. The retained reconstruction improves from 103 to 17 non-relocation byte differences over the complete 594-byte extent. It remains a partial, with no converted source or ledger replacement. The successful structural lever is explicit local references to the template name and shadow texture name before the visual call. This restores the receiver in EBX, the position in EDI, and the complete prologue and loop. Declaring the shadow type, name reference, and texture reference in that order reduces the tail further. Declaring the flag at template offset 0x48C before the flag at 0x48B reproduces the record construction schedule.

The retry hypothesis was that authentic helper visibility or incorrect declaration structure concealed the apparent register-allocation residue. Unchanged emitted instructions refuted the helper-visibility lever. The reference-local experiment supports the declaration-structure hypothesis by moving the first difference from +0x0D to +0x209 without changing the function size or relocation sites. This finding would be refuted by a probe of the saved bank at its normal path that restores the old 103-byte residue or changes the complete retail extent.
