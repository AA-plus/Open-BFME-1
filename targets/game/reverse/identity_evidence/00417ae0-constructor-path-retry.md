## Remaining blocker and checks

Retail saves EBX at +0x45, whereas the candidate saves it at +0xC1 and restores it at +0x123 instead of +0x15B. Before the late save, stack displacements are four bytes lower. The candidate caches the decrement import in EBP instead of ESI and uses ESI for the last two holder releases instead of EDI. `probe01.log` retains all instructions; `mismatch-bytes.json` lists all 163 differing masked byte offsets and relocation sites. Four relocation sites drift from their retail operand positions, so the 0.5546 score is a probe diagnostic and is not a fraction of verified reconstruction bytes.

The strict scoped gate fails on the byte differences and three unresolved opaque selector/emitter call views; `gate-candidate.log` is its unedited output. The displayed nonsensical assignment call destinations arise from the four-byte relocation-position drift, not evidence against the verified assignment pin. CSV validation, pin consistency, class gate and the source-level name-regression API pass. The requested name-regression CLI treats source paths as Git revisions and fails; `name-regression-cli.log` retains that limitation. Declared-unmatched checking rejects the bank's lack of a matched ledger row, as expected for an incomplete reconstruction. No pin, shared header, policy, game source or ledger change was made, so a full gate is not required for this preserved attempt.

Reopening requires independently supported source or lifetime evidence that explains the early EBX save and cleanup register choices.
