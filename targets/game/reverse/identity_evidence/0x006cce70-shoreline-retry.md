# Shoreline renderer retry at 0x006CCE70

The C++ reconstruction is a partial, not an exact recovery. The preferred candidate covers the complete 2268-byte extent. Its probe has 178 non-relocation byte differences and a measured quality of 0.9215. The scoped gate resolves relocations and finds 189 differing bytes, all between +0x1A5 and +0x2DC. The existing assembly ledger row remains unchanged.

The previous preferred body compiles to 1900 bytes with 1308 masked byte differences. Its 0.42 header was an author estimate. The revised body corrects the record layout, height samples, buffer arguments, render-state operations and object lifetimes before attempting scheduling changes.

## Hypothesis and refutation condition

The old bank reads cached vertex positions from a Zero Hour shoreline record and supplies a vertex-format mask where BFME supplies a format-table slot. Retail instead reads four float payloads from a 20-byte record, samples an unsigned-short height grid and passes slot 5 to the vertex-buffer access constructor. The current ledger supplies the producer, quad copier, native buffer methods, render-state diagnostic helpers and binding methods needed to compile those operations. The source files and complete decoded helpers were checked rather than treating their ledger names as type proof.

The retry hypothesis was that these independently verified declarations, native inline state operations and corrected lifetimes would improve a complete reconstruction over the saved body. A complete measured candidate that did not improve the old bank would refute it. The full-length near miss supports the hypothesis. It does not establish byte equality. The producer and quad helper were already mentioned in the earlier attempt; the improvement does not depend on claiming that those rows were newly landed.

## Record and sample types

The complete producer at 0x006C76B0 has one return, with `ret 0x14`, and no outgoing branch. At +0x44D through +0x450 it computes `count * 20` from the array pointer at owner +0x30C0. At +0x45F it writes packed integer coordinates at record offset zero. The stores at +0x45C, +0x46D, +0x47C and +0x48B write four floats at +4, +8, +0xC and +0x10. Every record field has independent instruction evidence. This is a raw record array, not an inferred STL value type.

The same producer reads the grid width at map +8, border at +0x10, data extent at +0x20 and sample pointer at +0x24. Its actual sample accesses read words with scale two. The target reads unsigned words and zero-extends them. The four target samples use the single index `y * width + x` and offsets zero, one, width plus one and width. Each height is multiplied by 0.0390625f. The record coordinates are decoded as a masked low word and an arithmetic-shifted high word. The world-coordinate scale is 10.0f.

The quad coordinates are consumed with four `fild dword` instructions. The complete 117-byte `__ftol2` helper at 0x009F6E38 consumes x87 ST0, returns its integer result in EDX:EAX and has no explicit stack arguments. This caller consumes EAX. The candidate's explicit integer-to-Real-to-Int conversions reproduce those calls. The quad helper takes an explicit output pointer; this is not hidden return storage.

The target's bit-plane query resolves through ILT 0x000489A5 to the complete 83-byte body at 0x0074B410. It accepts two 32-bit coordinates in stack order, reads dimensions at +8 and +0xC, byte-storage bounds at +0x28 and +0x2C, and byte-row stride at +0x34. Both returns use `ret 8`; the result is consumed as AL. The candidate preserves the existing `Gen_0074B410::bfmeBitA` declaration.

## Buffer layout, ABI and ownership

The complete constructor at 0x0091F730 writes the vertex access object's FVF-info reference at zero, type at +4, format slot at +8, start at +0xC, unsigned-short count at +0x10 and buffer pointer at +0x14. Lock and binding helpers independently read the unsigned-short offset at +0x12. Its four argument slots are type, format slot, count and start; both constructor returns clean 16 bytes and return the receiver in EAX. The target supplies 2, 5, 2048 and zero. The bank retains its established `BoxDynamicVBAccessClass` names.

The complete index access constructor at 0x0091D950 reads two unsigned-short arguments, stores type at zero and count at +4, clears the buffer at +8 and returns with `ret 8`. The locks at 0x0091F160 and 0x0091D410 each store an access pointer at zero and an output pointer at +4. All their return paths clean one four-byte argument and return the lock receiver. The vertex lock uses a 44-byte vertex stride. The target writes only x, y, z, u1 and v1 in each vertex; it does not initialize the remaining fields as the old bank did.

The target binds both buffers while the lock objects are still alive. It then destroys the index lock, vertex lock, index access and vertex access before drawing. The index lock increments and decrements the underlying buffer's reference count, and both lock destructors finish by tail-dispatching to the complete 95-byte body at 0x00905B10. That body uses the PE-recorded critical-section and mutex imports and returns AL; the destructor callers discard it. Complete decoded buffer setters confirm the reference operations and every field offset consumed by the candidate's binding calls.

## Unwind and indirect state calls

`eh-target.txt` and the raw FuncInfo in `flow-audit-v2.txt` establish eight unwind states and no try-block map. States 0 and 1 destroy temporary strings at EBP -0x98. States 2 through 5 destroy vertex access, index access, vertex lock and index lock at EBP -0x28, -0x44, -0x58 and -0x64. State 6 destroys the cold-path string at EBP -0x90 before state 5; state 7 destroys the normal restoration string at EBP -0x90. Their predecessor sequence is `[-1, -1, -1, 2, 3, 4, 5, -1]`.

`compiled-eh-v2.txt` independently reads the candidate's COFF FuncInfo, unwind map and cleanup instructions. Its state predecessors, receiver offsets and destructor targets reproduce that sequence. The target's string cleanup route goes through 0x0013A050 to `StringClass::Free_String` at 0x009DB7A0. The complete string allocation and release bodies were decoded. The old explicit try/catch and extra exception helper are absent from retail and were removed from the reconstruction.

The native render-state diagnostics are real calls despite the release build. The complete diagnostic bodies at 0x00907BE0 and 0x00906FE0 were decoded, including every switch-table destination and tail route. `flow-audit-v2.txt` separates their embedded or adjacent tables from instructions; it does not treat table bytes as code. Their tails reach the complete variadic `StringClass::Format` body at 0x009DBB90, which reads its receiver and format from stack slots and leaves caller cleanup intact.

The target's render-state device calls use slot +0xE4 with three four-byte stack arguments including the explicit device receiver. Its texture-stage call uses slot +0x10C with four four-byte arguments including that receiver. Neither call has caller cleanup. The canonical device header emits +0x118 for the texture-stage method, so the bank uses an address-derived table adapter at +0x10C. No new pin is introduced. The return value of this external device call is unused; its HRESULT declaration follows the vendor interface rather than a decoded implementation. The exact runtime implementation and slot identity remain unverified and must be resolved before claiming a fully verified recovery.

## Measured alternatives and reopening

All trial sources and raw probe outputs remain under `build/shore-006cce70/`. The first complete native-header trial was 2220 bytes with 1593 masked differences. Correcting the receiver adapter and sampled-height lifetime led to 2257 bytes with 1467 differences. A single sample index reduced the candidate to 2256 bytes with 1356 differences and only six normalized structural differences. Ordering the matrix stores and cached state read produced the preferred 2268-byte trial with 178 masked differences.

The EHsc and STLport exception variants did not change the saved body's compiler result. Two bounded register variants did not improve their control candidate. Native Matrix3D versus Matrix4 identity construction did not change the single-index result. Nonvolatile world and cached-color variants produced 2268 bytes with 200 or 455 masked differences. Adding the native snapshot diagnostic macro did not improve the 455-difference result. An unused volatile cache preload retained a duplicate read and produced 2270 bytes with 1385 differences. The P6 scheduling flag left the 2256-byte control unchanged. These outcomes are retained in `probe*.txt`; compile failures are retained separately and are not treated as compiler measurements.

The bounded store-order and loop-header search is in `build/shape_search/20ce7fa02e0b4e5295a6b641602b8fb7/`. All eight trials retained the same measured score as the preferred candidate. The two register searches and the EH search have their own `result.json` and raw logs under `build/shape_search/` and `build/shore-006cce70/`.

The scoped identifier check initially found substitutions involving the native wrapper qualifier and the bank's `getQuickFlipState` spelling. The final bank retains the latter as a private macro adapter to the independently decoded bit-plane call, and gives the newly introduced static state adapter its own descriptive name. `names28.txt` reports no scoped identifier regressions. A function adapter added 12 masked differences, so that form was rejected. The final macro form reproduces the preferred instruction and relocation result and its 178 masked differences. The single verdict row is unchanged; the corrected preferred source and its immutable archive are retained separately.

Reopening is justified by a concrete native render-state declaration or inline shape that preserves the cached flags across the identity stores, reads the color cache into the retail register role, and retains the alpha value across diagnostics. The remaining relocated mismatch is confined to that first setup block. Repeating the listed spelling, register and exception variants supplies no new evidence. The external texture-stage slot identity also remains a separate verification obligation. No exact C++ bytes are claimed or added to progress.
